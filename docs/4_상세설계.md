# 상세 설계

[아키텍처](3_아키텍처.md)에서 정한 구조의 세부 규격이다. 계산 공식은 [계산 규칙](2_계산규칙.md)에 있다.

## 1. 데이터 출처: Yahoo Finance (비공식)

### 일별 종가
```
GET https://query1.finance.yahoo.com/v8/finance/chart/{symbol}
    ?period1=0&period2={지금+1일 유닉스초}&interval=1d&events=split
헤더: User-Agent: Mozilla/5.0   (없으면 막힌다)
```
- `period1=0`이면 상장 이후 전체가 **일봉으로** 온다 (QQQ 6,971일, 2026-11-24 확인).
- 응답에서 쓰는 것:
  - `meta.currency`, `meta.gmtoffset`, `meta.exchangeTimezoneName`, `meta.longName`/`shortName`
  - `timestamp[]`, `indicators.quote[0].close[]` (분할 반영 종가), `indicators.adjclose[0].adjclose[]` (배당까지 반영. 받아서 저장만 하고 계산에는 쓰지 않는다, 결정 d36)
  - `events.splits` (분할 날짜와 비율, 안내용)
- `close`가 `null`인 날은 건너뛴다. 날짜 변환은 [계산 규칙](2_계산규칙.md) 1절.
- 없는 종목은 HTTP 404 또는 `chart.result`가 비어 있다.
- 환율도 같은 주소다: `USDKRW=X`. `KRW=X`와 같은 데이터다.

### 검색
```
GET https://query1.finance.yahoo.com/v1/finance/search?q={검색어}&quotesCount=8&newsCount=0
```
- `quotes[]`의 `symbol`, `shortname`/`longname`, `exchDisp`, `quoteType`을 쓴다.
- `quoteType`이 EQUITY, ETF, INDEX, MUTUALFUND, CRYPTOCURRENCY인 것만 남긴다 (OPTION 등 제외).
- 한글 같은 검색어에는 HTTP 400 `"Invalid Search Query"`를 준다 (2026-11-25 확인). 본문의 `finance.error.description`이 이 문구일 때만 결과 없음으로 보고 `[]`를 돌려준다. 그 밖의 400·4xx·5xx는 503이다.
- 한글 이름은 못 찾는다. 코드와 영문 이름은 된다.

### 주의
- 공식 API가 아니다. 주소나 응답이 바뀌면 멈출 수 있고, 너무 자주 부르면 429로 막힌다.
- 이용약관상 개인 용도로 쓴다. 공개 서비스로 키우면 데이터 출처를 바꾼다 (예: Twelve Data, Alpha Vantage, 한국 종목은 증권사 Open API). 그래서 `market.py`는 "종목 코드 → 날짜·종가 목록"이라는 한 가지 함수로만 바깥에 보이게 한다.

## 2. 캐시 파일

`data/prices/{종목코드}.json`. 종목 코드를 대문자 그대로 파일 이름으로 쓴다 (`QLD.json`, `USDKRW=X.json`, `005930.KS.json`).

```json
{
  "symbol": "QLD",
  "name": "ProShares Ultra QQQ",
  "currency": "USD",
  "exchange_tz": "America/New_York",
  "fetched_at": 1795500000,
  "dates":    ["2006-06-21", "2006-06-22", "..."],
  "close":    [0.0, 0.0],
  "adjclose": [0.0, 0.0],
  "splits":   [["2025-11-20", "2:1"]]
}
```

- `dates`는 거래소 현지 날짜, 오름차순, 중복 없음. `close`(분할 반영)와 `adjclose`(배당까지 반영, 저장만 하고 계산에는 쓰지 않음)는 `dates`와 길이가 같다. 날짜마다 객체를 두지 않고 열마다 배열로 둔다. 엔진에는 `dates`·`close`를 그대로 넘긴다.
- `fetched_at`(유닉스초)이 6시간 안이면 다시 받지 않는다.
- **받을 때마다 그 종목 전체를 다시 받아서 파일을 통째로 바꾼다.** 분할이 생기면 Yahoo가 과거 종가를 전부 다시 계산하기 때문이다 ([아키텍처](3_아키텍처.md) 4절).
- 저장은 같은 폴더의 임시 파일에 다 쓴 뒤 `os.replace`로 바꿔치기한다. 쓰다가 죽어도 깨진 파일이 남지 않는다.
- 종목별 잠금을 읽을 때도 건다. 윈도우에서는 누가 파일을 열고 있으면 바꿔치기가 실패한다. 같은 종목을 동시에 두 번 받는 일도 막는다.
- 받기에 실패하면 저장된 값으로 계산하고, 응답에 `stale: true`와 마지막 날짜를 넣는다. 저장된 것도 없으면 그 종목만 오류로 돌려준다.
  - "받기 실패"에는 네트워크·HTTP 오류, 응답 모양이 예상과 다른 경우, 저장본이 있던 종목을 Yahoo가 갑자기 없다고 하는 경우(상장 폐지 등)가 모두 들어간다.
- 파일이 깨져서 읽히지 않으면 없는 것으로 보고 다시 받는다.

## 3. 계산 엔진 (`engine.py`)

입출력 없이 데이터만 받아 계산한다. 그래서 저장된 fixture로 바로 테스트할 수 있다.

```python
@dataclass
class Series:            # main.py _to_series가 market의 PriceHistory로 만든다
    symbol: str
    currency: str
    dates: list[date]    # 오름차순, 중복 없음
    close: list[float]
    exchange_tz: str = ""   # 거래소 시간대 (Yahoo exchangeTimezoneName). 모르면 "". 같은지만 본다

@dataclass
class Params:
    start: date; end: date
    freq: Literal["daily", "weekly", "monthly"]
    anchor: int | None   # weekly 0~4(월~금), monthly 1~31
    amount: float        # 투자 통화
    currency: str        # "KRW" | "USD"
    fractional: bool = True
    fee: float = 0.0     # 0.0025 = 0.25%

def buy_days(dates, start, end, freq, anchor) -> list[date]
def simulate(asset: Series, fx: Series | None, p: Params) -> SimResult
    # SimResult: summary(Summary), buys(list[BuyRow]), daily(list[DailyRow]) — 모두 dataclass
    # BuyRow.return_pct는 그날 수익률(그 매수일의 daily 값, 마지막 날은 다시 평가한 값), lot_return_pct는
    # 이 회차 지금(9-1, %, qty 0이면 None). 평가 가격·환율을 루프 앞에서 구해 줄을 만들 때 채우고,
    # 마지막 거래일 매수 줄의 return_pct만 평가 환율로 다시 평가한 값으로 바꾼다 (결정 d59)
def xirr(flows: list[tuple[date, float]]) -> float | None
def rate_on(fx: Series | None, day: date) -> float
    # 환율 (3절): day 당일 또는 그 이전 마지막 종가. fx가 None이면 1, 이전 값이 없으면 EngineError
    # 9-5 양도세 환율(USDKRW=X)도 main이 이 함수로 찾는다
def build_chart(results: dict[str, SimResult], max_points=1000) -> Chart
    # 모든 종목 거래일을 합친 날짜축, 없는 날은 직전 값, 최대 max_points로 줄이기
    # Chart: dates, series(종목별 ChartSeries: value·invested·return_pct·price·avg_cost·drawdown),
    # total_days(줄이기 전 날짜 수). drawdown은 9-1 평가금 낙폭(%)이고 analyze와 같은 함수로 계산한다
def analyze(result: SimResult, asset: Series, fx: Series | None, end: date, *, tax_fx: float) -> Analysis
    # v2 지표 (계산 규칙 9-1~9-5): 낙폭, 원금 아래, 연도별, 월별, 수익 분해, 양도세
    # 싸게 산 횟수는 qty 0인 매수일(쉰 날, 정수 주로 못 산 날)을 세지 않는다 (결정 d58)
    # asset은 끝날짜로 자르지 않은 전체 데이터다 (9-3 끝난 달은 2절 매수일처럼 데이터 마지막 날을 본다)
    # tax_fx는 투자 통화 1단위의 원화 값 (원화 투자면 1, 달러 투자면 끝날짜 당일 또는 그 이전 마지막
    # USDKRW=X 종가, 9-5). 기본값 없음, 0 이하면 ValueError
def same_exchange(a: Series, b: Series) -> bool
    # exchange_tz가 둘 다 비어 있지 않고 같을 때만 True (9-6, 결정 d29). API의 switch_ref.basis도 이것으로 정한다
def simulate_with_rule(asset, fx, ref: Series | None, p: Params, rule, ma_days=200) -> SimResult
    # 매수 규칙(F-17)으로 산 결과를 simulate와 같은 모양으로. rule은 none·ma_dip·ma_hot·switch, lump_sum이면 ValueError
    # 9-6 소수점 매수(p.fractional은 보지 않음). buys는 매수일마다 한 줄이고 쉰 날은 qty 0, cash는 남은 현금(종목 통화)
    # avg_cost_invest는 None (결정 d39). invested는 A × 매수 횟수
def simulate_rule(asset, fx, ref: Series | None, p: Params, rule, ma_days=200) -> StrategyResult
    # simulate_with_rule과 같은 계산 루프를 쓰고 결과를 StrategyResult로 바꾼다
    # 같은 예산 전략 (9-6): none·ma_dip·ma_hot·switch·lump_sum. ref는 레버리지 전환의 기준 종목. 소수점 매수
    # switch: same_exchange(asset, ref)면 매수일의 종가·이평선을 보고,
    # 아니면(다르거나 하나라도 비어 있으면) 매수일보다 앞선 마지막 거래일 기준 (9-6)
def build_strategy_chart(results: Sequence[StrategyResult], max_points=1000) -> StrategyChart
    # 전략별 평가금 추이 (F-15). 날짜축은 전략의 daily 날짜(같은 조건으로 계산한 전략은 모두 같다). 줄이기는 build_chart와 같은 규칙
    # StrategyChart: dates, series(전략별 value·invested·return_pct, 빈 값 없음), total_days
    # 날짜축이 다르거나 같은 전략이 두 번이면 ValueError
def anchor_sweep(asset, fx, p) -> dict[int, float | None]   # 매월 1~28일·말일의 평단가 (9-7)
def start_sweep(asset, fx, p) -> dict[str, float]            # 각 달 1일 시작의 수익률 (9-7)
```

- `tests/reference_calc.py`의 함수 구조를 그대로 가져와도 된다. 다만 `simulate`는 매수일만이 아니라 거래일마다 평가금·투자금·수익률(`daily`)도 만든다.
- XIRR은 뉴턴법으로 풀고, 수렴하지 않으면 이분법(−99.99% ~ +10,000%)으로 넘어간다. 해가 없거나 구간 밖이면 `None`.
- 계산할 수 없는 데이터(기간 안 매수일 없음, 환율 없음)는 `EngineError`, 입력 계약 위반(금액 0, 통화와 환율 인자가 안 맞음)은 `ValueError`다. API는 앞의 것을 종목별 `errors`로 돌려준다.
- 그래프용으로 줄일 때는 일정 간격으로 고르되 **첫날, 마지막 날, 최고·최저 수익률 날짜는 꼭 남긴다.** 종목 그래프는 종목마다 평가금 최대 낙폭 날짜도 남긴다(낙폭 그래프의 가장 낮은 점이 `summary.max_drawdown`과 같다). 전략 그래프는 전략마다 최고·최저 수익률 날짜를 남긴다.

## 4. API

### `GET /api/search?q=qld`
```json
[{"symbol": "QLD", "name": "ProShares Ultra QQQ", "exchange": "NYSEArca", "type": "ETF"}]
```

### `POST /api/backtest`
요청
```json
{
  "symbols": ["QQQ", "QLD"],
  "start": "2021-11-25",
  "end": "2026-11-24",
  "freq": "monthly",
  "anchor": 1,
  "amount": 2000000,
  "currency": "KRW",
  "fractional": true,
  "fee_pct": 0,
  "tax": true,
  "rule": "none",
  "ma_days": 200,
  "switch_ref": "QQQ",
  "include_daily": false
}
```
검사: 종목 1~8개, 형식 `^[A-Za-z0-9.\-=^]{1,20}$`, `start < end ≤ 오늘`, `amount > 0`, `fee_pct` 0~10, freq에 맞는 anchor 범위, `tax`는 true/false(기본 false, F-20 양도세 어림), `rule`은 none·ma_dip·ma_hot·switch(기본 none, F-17), `ma_days`·`switch_ref`는 `/api/strategy`와 같다(기본 200·QQQ), `include_daily`는 true/false(기본 false, 아래 `daily`). `switch_ref` 형식은 rule과 상관없이 본다. 어기면 422와 항목별 메시지.

- 종목 하나가 실패해도 나머지 결과는 돌려준다 (`errors`에 따로). 환율을 받지 못한 종목도 그 종목만 실패한다 ("USDKRW=X 환율을 받지 못해 계산하지 못했습니다.").
- `notes`는 시작일 뒤의 분할이다. 끝날짜 뒤의 분할도 가격·수량에 반영돼 있어서 같이 적는다.
- `tax`가 켜진 달러 투자에서 양도세용 `USDKRW=X`를 받지 못하면, 원화가 아닌 종목은 모두 그 종목 오류다 (결정 d40). 메시지는 환율 실패와 같다.
- `stale`이면 저장본(종목이나 환율. 양도세용 `USDKRW=X`도 포함)으로 계산했고, `data_through`는 평가에 쓴 마지막 거래일이다. `listed_from`은 상장일이 시작일보다 늦을 때만 그 첫 거래일이다.
- `stale_sources`는 그 종목 계산에 저장본으로 쓴 코드마다 한 줄 `{symbol, kind, data_through}`이다 (F-10).
  - `kind`는 `price`(종목 주가), `fx`(매수·평가 환율), `tax_fx`(양도세 환율)이고 줄도 이 순서다.
  - `data_through`는 그 코드의 끝날짜 당일 또는 그 이전 마지막 거래일이다 (계산 규칙 3절 평가 환율과 같은 규칙). `price`면 결과의 `data_through`와 같다.
  - 같은 환율을 여러 종목이 쓰면 종목마다 같은 줄이 들어간다. 알림을 하나로 합치는 일은 화면이 한다.
  - 기준 종목은 넣지 않는다 (`switch_ref`). `stale`은 `stale_sources`가 비어 있지 않은 것과 같다.
- 엔진에는 끝날짜로 자르지 않은 전체 데이터를 넘긴다 (결정 d32. 9-3 끝난 달은 데이터 마지막 날을 본다).
- `summary`의 v2 지표는 [계산 규칙](2_계산규칙.md) 9-1·9-4·9-5다. 금액은 투자 통화, 비율은 %다.
  - 값이 없을 때 (결정 d25): 낙폭이 없으면 `max_drawdown`, 원금 아래였던 적이 없으면 `longest_underwater`·`last_underwater`가 `null`이다. 끝까지 원금 위로 못 올라왔으면 `recovered`가 `null`이다. 투자 통화와 종목 통화가 같으면 `avg_buy_fx`가 `null`이고 `fx_effect`는 0이다.
  - `tax: false`면 `tax`·`profit_after_tax`가 `null`이다. 한국 종목은 0이다. 달러 투자면 끝날짜 당일 또는 그 이전 마지막 `USDKRW=X` 종가로 원화 공제를 계산한다 (9-5). 이 환율은 요청 하나에 한 번만 받는다.
  - 반올림 뒤라 `price_effect + fx_effect`가 `profit`과 1원 다를 수 있다.
- `analysis`는 9-1·9-2·9-3이다. `years` 키는 "YYYY", `months` 키는 "YYYY-MM"이고 둘 다 오름차순이다. `months` 값은 %이고 `/api/strategy`의 `start_sweep`과 같은 모양이다. 매수 가격 목록은 따로 두지 않는다. 같은 응답의 `buys[].price`(줄이지 않은 전체)를 쓴다.
- `chart.series` 값은 그 종목 첫 매수 전 날짜에서 `null`이다. `value`·`invested`는 투자 통화, `price`·`avg_cost`는 종목 통화, `drawdown`은 그날 평가금 낙폭(%)이다.
- 저장본으로 4종목(QQQ·QLD·TQQQ·SOXL) 5년 매일 `tax: true` 요청 하나는 개발 PC에서 약 0.06초, 응답은 약 1.2MB다 (매수 내역 두 열을 더하기 전 약 970KB). 기준은 1초다 (비기능 "속도"). `rule: switch`도 같은 기준을 지킨다. `include_daily: true`면 응답이 약 1.4MB로 늘고 시간은 거의 같다.
- 매수 규칙(`rule`이 none이 아님, F-17)
  - 9-6 같은 예산 규칙으로 계산한다. 소수점 매수라 `fractional`은 쓰지 않는다 (결정 d28과 같은 취지, `params.fractional`은 보낸 값 그대로).
  - `avg_cost_invest`는 `summary`와 `buys` 모두 `null`이다 (결정 d39). `buys`는 매수일마다 한 줄이고, 레버리지 전환에서 쉰 날은 `qty` 0이다. `leftover_cash`는 남은 현금(종목 통화)이다.
  - 환율 효과(`fx_effect`)와 평균 매수 환율은 규칙과 상관없다 (9-4).
  - `analysis.buys_below_eval_price`·`buys_below_avg_cost`는 쉰 매수일(qty 0)을 세지 않는다 (9-1, 결정 d58). 9-8 조건의 레버리지 전환은 산 45번 중 36번·12번이다. 산 횟수는 `buys`에서 `lot_return_pct`가 `null`이 아닌 줄 수다 (`qty`는 소수 4자리로 반올림해 아주 적게 산 회차가 0으로 보일 수 있다).
  - `switch`면 기준 종목을 환율 없이 받는다. 요청 종목과 같으면 그 데이터를 쓰고, 종목이 여럿이어도 한 번만 받는다. `results[].switch_ref`는 `/api/strategy`와 같은 모양 `{symbol, basis, stale, data_through}`이고 다른 규칙이면 `null`이다. 기준 종목이 저장본이면 여기의 `stale`만 켠다.
  - 기준 종목을 받지 못하면 모든 종목이 그 규칙으로 계산할 수 없으므로 종목마다 오류다: "기준 종목 QQQ를 받지 못해 계산하지 못했습니다." 종목·환율을 받지 못한 오류가 있으면 그것이 먼저다. `/api/strategy`는 레버리지 전환만 빼지만(결정 d31), 여기는 결과 전체가 그 규칙이라 다르다.
- `chart.total_days`는 줄이기 전 날짜 수다. `dates`보다 많으면 화면이 그래프 아래에 "기간이 길어 그래프는 2,513일 중 998점만 골라 그렸습니다…"처럼 알린다 (F-07).
- `buys`는 줄이지 않는다. 매일 매수 10년이면 종목당 약 2,500줄이다.
  - `return_pct`는 그날 수익률(그 매수일의 수익률 추이 값, 9-1·5절)이고 같은 날 `chart.series[종목].return_pct`와 같다. `lot_return_pct`는 이 회차 지금(그날 산 몫만 끝날짜에 팔았을 때의 투자 통화 수익률, 9-1)이고 산 수량이 0인 줄은 `null`이다 (결정 d59). 둘 다 %다. 정수 주만·매수 규칙에도 같은 식이다. 반올림해 0이 되는 값은 `-0.0`이 아니라 `0.0`으로 보낸다 (`daily.return_pct`도 같다).
- `daily`는 `include_daily: true`일 때만 채운다 (결정 d60). 꺼져 있으면 `null`이다.
  - 모양: `{"dates": [...], "value": [...], "invested": [...], "return_pct": [...]}`. 그 종목의 첫 매수일부터 `data_through`까지 거래일마다 한 값이고 줄이지 않는다. 그래서 길이는 `summary.trading_days`와 같고, 마지막 `value`는 `summary.value`다.
  - 자리수는 `chart`와 같다 (`value`·`invested`는 투자 통화 금액, `return_pct`는 소수 2자리 %).
  - 화면은 CSV의 "날마다 평가금 넣기"를 켜고 내려받을 때만 같은 조건으로 다시 부른다. 평소 응답 크기와 속도는 그대로다.
- 숫자 반올림은 [계산 규칙](2_계산규칙.md) 5절 끝의 "응답 자리수"를 따른다.

오류 응답
```json
// 422 입력 오류: 항목별로
{"detail": [{"field": "anchor", "message": "매주 매수 요일은 0(월)~4(금) 중 하나입니다"},
            {"field": "start", "message": "시작일은 끝날짜보다 앞이어야 합니다"}]}
// 503 검색 실패
{"detail": "종목을 검색하지 못했습니다. 잠시 뒤 다시 시도해 주세요."}
```
- "오늘"은 한국 날짜다.
- 검사는 두 단계다. 한 항목만 보고 알 수 있는 오류(종목 개수·형식, 금액, 수수료, 날짜 형식)가 있으면 그 오류만 먼저 돌려준다. 그게 없을 때 항목끼리 맞추는 오류(기준일, 시작일 ≥ 끝날짜, 끝날짜 > 오늘)를 모아서 돌려준다.

### `POST /api/strategy`
전략 비교(F-15)용이다. 종목 하나를 같은 예산 전략 5개로 계산하고([계산 규칙](2_계산규칙.md) 9-6), 전략별 평가금 추이와 매수일·시작 시점 바꿔 보기(9-7)도 같이 돌려준다. 요청이 무거워서 `/api/backtest`와 따로 둔다.

요청: 조건 항목(`start`·`end`·`freq`·`anchor`·`amount`·`currency`·`fractional`·`fee_pct`)은 `/api/backtest`와 같고, 종목 목록 대신 아래 셋이 있다.
```json
{
  "symbol": "QLD",
  "start": "2021-11-25", "end": "2026-11-24",
  "freq": "monthly", "anchor": 1, "amount": 2000000, "currency": "KRW",
  "fractional": true, "fee_pct": 0,
  "ma_days": 200,
  "switch_ref": "QQQ"
}
```
검사: 조건 항목은 `/api/backtest`와 같다. `symbol`·`switch_ref`는 종목 코드 형식, `ma_days`는 20·60·120·200 중 하나(기본 200), `switch_ref` 기본은 QQQ. 오류 모양과 두 단계 검사도 같다.

응답 (위 요청, fixture 기준 실제 값. `expected.json`의 `v2`와 같다)

- `strategies`의 키와 순서는 `engine.RULES`(none·ma_dip·ma_hot·switch·lump_sum)와 같다. 안쪽 이름은 `expected.json` `v2.strategies`와 같고 `invested`가 하나 더 있다. 일시금을 포함한 5개 모두 같은 총액이다 (9-6).
- 금액(`value`·`invested`·`leftover_cash_invest`)은 투자 통화, `avg_cost_asset`은 종목 통화다. `rule_days`는 규칙이 걸린 매수일 수다 (이평선 아래·과열·쉰 날). 반올림은 [계산 규칙](2_계산규칙.md) 5절 끝을 따른다.
- 전략은 소수점 매수로 계산한다. `fractional: false`여도 값이 같다 (결정 d28).
- 엔진에는 시작일·끝날짜로 자르지 않은 전체 데이터를 넘긴다. 이평선은 시작일 이전 주가를 쓰고(9-6), 진행 중인 달은 데이터 마지막 날로 판정한다(2절).
- 기준 종목은 환율 없이 받는다. 기준 종목이 종목과 같으면 한 번만 받는다.
- `switch_ref.basis`는 레버리지 전환이 기준 종목의 어느 날 종가·이평선을 봤는지다 (결정 d29). `same_day`는 같은 거래소라 매수일 것을, `previous_day`는 다른 거래소이거나 시간대를 몰라 매수일보다 앞선 마지막 거래일 것을 봤다는 뜻이다. `switch_ref.data_through`는 기준 종목의 끝날짜 당일 또는 그 이전 마지막 거래일이고 없으면 `null`이다 (결정 d45). 저장본 알림에 기준일로 적는다.
- `stale`은 종목이나 환율을 저장본으로 계산했다는 뜻이고, 기준 종목이 저장본이면 `switch_ref.stale`에 따로 적는다. `notes`·`data_through`·`listed_from`은 `/api/backtest`와 같은 뜻이다.
- `chart`는 전략별 평가금 추이다.
  - 날짜축은 첫 매수일부터 `data_through`까지의 거래일이다. 전략이 모두 같은 날짜를 써서 `null`이 없다.
  - `series` 키는 계산한 전략만 `engine.RULES` 순서로 들어간다. `value`·`invested`는 투자 통화, `return_pct`는 %다.
  - 줄이기와 `total_days`는 `/api/backtest`의 `chart`와 같다. 최고·최저 수익률 날짜는 전략마다 남긴다.
- `anchor_sweep`은 매월 1~28일과 말일(키 `"31"`)에 샀을 때의 평단가다(종목 통화, 소수 4자리). 키는 29개이고, 위 예는 그중 일부다. `start_sweep` 예(54개 중 일부)도 같다.
  - 요청 주기와 상관없이 매월로 계산한다 (9-7, 결정 d27).
  - 그 기준일로는 기간 안에 매수일이 없거나, 정수 주만 살 때 한 주도 사지 못했거나(평단가가 없음), 그 기준일로 사는 날 환율이 없으면(환율 데이터가 더 늦게 시작) `null`이다 (결정 d56).
- `start_sweep`은 시작일을 각 달 1일로 바꿔 끝날짜까지 계산한 수익률(%)이다. 키는 `"YYYY-MM"` 오름차순이다.
  - 범위는 1일이 시작일 당일이나 그 뒤인 달부터, 끝날짜가 든 달의 6개월 전 달까지다. 상장 달보다 앞선 달은 뺀다.
  - 시작할 달이 없으면 `{}`다.
- 두 바꿔 보기는 2·4절 그대로 요청의 조건(수수료, `fractional`)으로 계산하고, 기준 종목과 `ma_days`는 쓰지 않는다. 전략은 소수점 매수로만 계산하므로(결정 d28) `fractional: false`면 같은 응답 안에서 계산 방식이 다르다. 그 대신 매월 요청이고 기준일이 1~28일이나 31일이면, 그 기준일의 `anchor_sweep` 값이 `/api/backtest` 평단가와 같다. 기준일 29·30인 요청과 매일·매주 요청은 `anchor_sweep`에 지금 조건의 점이 없다 (화면 표시는 13단계에서 정한다).
- 응답은 그래프 때문에 5년 매일이면 약 160KB다. 저장본으로 5년 매일 요청 하나는 개발 PC에서 0.2~0.26초다. 2초 기준은 요청 하나마다 잰다 (결정 d30).

오류
- 종목이나 환율을 못 받았거나 기간 안에 매수일이 없으면 200, `result: null`, `errors`에 그 종목을 적는다. 메시지는 `/api/backtest`와 같다.
- 기준 종목만 못 받으면 레버리지 전환만 뺀다: `strategies.switch: null`, `switch_ref: null`, `chart.series`에 switch 키 없음, `errors`에 기준 종목. 나머지 4개 전략과 두 바꿔 보기는 그대로 돌려준다 (결정 d31).
- 매수일 바꿔 보기의 한 기준일만 계산할 수 없으면(그 기준일로 사는 날 환율이 없음) 그 키만 `null`이고 `result`·`errors`는 그대로다 (결정 d56). 시작 시점 바꿔 보기는 요청의 매수일 중 일부로 계산해서, 요청이 계산되면 같은 이유로 실패하지 않는다.
- 둘 다 실패하면 `errors`에 종목 줄이 먼저, 기준 종목 줄이 그다음이다.

### `GET /` 와 정적 파일
`web/` 폴더를 그대로 제공한다.

### v2에서 더할 것
- `/api/backtest`의 v2 요청(`tax`, `rule`·`ma_days`·`switch_ref`)과 응답(v2 지표, `analysis`, `drawdown`, `switch_ref`)은 위 `/api/backtest` 절에 있다 (#35·#36). 비율로 나누기(F-18, 결정 d37)와 배당 재투자(F-19, 결정 d36)는 뺐다.
- `POST /api/strategy`: 위 [`POST /api/strategy`](#post-apistrategy)에 있다 (11단계). 기준값은 `expected.json`의 `v2`(키 이름이 응답 이름과 같다). 그 안의 `dollar_tax`(달러 투자 양도세), `switch_cross_exchange`(다른 거래소 기준 종목의 레버리지 전환), `buy_rows`(매수 내역 1·14·60회의 `return_pct`·`lot_return_pct`, 날짜 키), `rule_bought`(매수 규칙 결과의 산 횟수와 `buys_below_*`)는 응답 이름이 아니라 검증용 사례다.

B에 없는 v2 요소는 B의 토큰과 부품으로 맞춘다. 데스크톱 웹만 만든다 (1280px 기준, 1024px까지).

- 틀은 화면 전체 폭이다. 머리는 높이 60px 띠로 위에 붙는다. 조건 패널은 머리 아래부터 창 바닥까지 이어지는 왼쪽 띠(고정폭 340px, 1100px 이하 320px, 긴 종목 이름에도 넓어지지 않는다)이고, 결과는 나머지 폭이다. 1024px 폭에서도 둘이 나란히 보인다. 패널은 스크롤해도 머리 아래에 붙어 있고 높이는 창 높이 − 60px라, 창보다 길면 패널 안에서 스크롤한다 (얇은 스크롤 막대. 페이지 맨 위에서도 계산하기에 늘 닿는다).
- 테마는 처음엔 다크(B)로 연다. 머리의 버튼으로 바꾸면 이 브라우저에 남긴다(`localStorage` "theme"). 운영체제 설정은 따르지 않는다 (결정 d47).
- 상태: 처음(입력만) → 계산 중(버튼 잠금, 종목별 진행) → 결과 / 일부 오류 / 전체 오류. 시안 "v1 · 상태" 보드에 모두 그려 두었다.
- v2 결과 탭 (F-11). 위에서부터 결과 머리 줄(조건 한 줄·링크 복사·CSV) → 알림 → 탭 `[요약][분석][전략 비교][매수 내역]` → 탭 내용 → 고정 안내. 머리 줄·알림·안내는 어느 탭에서나 보인다.
  - 요약: 한눈에 요약 → 카드 → 비교 표 → 그래프. 매수 내역: 매수 내역 표와 CSV 내려받기. 분석은 바로 아래 줄이다. 전략 비교(F-15)는 13단계에서 채우고, 그때까지 "다음 단계에서 채웁니다" 안내만 둔다 (결정 d41).
  - 분석 (F-14, 시안 v2 분석 보드). 위에서부터 탭 맨 위 한 줄 → 묶음 상자 → 탭 끝 안내다. 묶음은 얼마나 흔들렸나(#60), 연도별 결과·달마다 얼마나 움직였나(#61), 수익은 어디서 왔나·얼마에 샀나(#64)다. 글·표 줄·그래프 좌표(DOM 없는 부분)는 `web/analysisdata.js`, 그리기는 `web/analysis.js`에 있다. 탭을 바꿔도 다시 계산하지 않는다.
    - 탭 맨 위: "결과를 여러 각도로 나눠 봅니다. 금액은 원화 기준입니다." 통화는 투자 통화 이름이다. 매수 가격은 종목 통화라 시안의 "숫자는 모두 원화 기준"을 쓰지 않는다.
    - 얼마나 흔들렸나 표 (9-1). 열: 종목(견본·코드), 최저 수익률(날짜), 평가금 최대 낙폭(날짜), 원금 아래였던 날(일수와 비율 소수 1자리, 카드와 같은 글), 가장 길게 원금 아래(거래일, 시작 달 ~ 회복 달), 마지막으로 원금 아래. 표 안 날짜는 시안처럼 짧게 쓰고("22-12-28", 달은 "22-09"), 마지막으로 원금 아래만 "2023-05-04"로 쓴다. 최저 수익률·낙폭은 화면에 보이는 1자리 값으로 손익 색과 기호를 붙인다. 정렬과 굵게는 없다.
      - 값이 없을 때 (결정 d25): 낙폭이 없으면 "없음", 원금 아래였던 적이 없으면 "0일 (0.0%)"과 가장 길게·마지막 "없음", 끝까지 원금 위로 못 올라왔으면 "22-03 ~ 회복 전".
      - 표 위 글: "적립식은 넣은 돈이 계속 늘어서, 수익률과 평가금 기준 낙폭을 같이 봅니다. 전체 1,250 거래일 기준." 거래일 수(`trading_days`)가 종목마다 다르면 끝 문장을 "거래일 수는 종목마다 다릅니다."로 쓴다. 넓으면 표 안에서만 가로로 민다.
    - 낙폭 그래프 (같은 상자, 표 아래). 소제목 "평가금 최고점 대비 낙폭"과 범례(견본·코드·최대 낙폭, 버튼이 아니다). `chart.series[].drawdown` 선을 SVG로 그려 Chart.js를 못 불러와도 보인다. 종목 색·선 모양 1.8px이고 첫 종목이 맨 위다. 화면에서 점을 더 줄이지 않는다. 서버가 종목마다 최대 낙폭 날을 남기므로(3절) 가장 낮은 점이 표의 최대 낙폭과 같다.
      - 세로축은 모든 선이 같이 쓴다. 0%(진한 선)에서 바닥까지이고, 바닥은 가장 깊은 낙폭을 눈금 간격(20% 이하 5, 50% 이하 10, 그보다 깊으면 25)으로 내린 값이다. 낙폭이 모두 0이면 −5%다. 예시 4종목(최저 −90.9%)은 시안처럼 0 ~ −100%, 25 간격이다.
      - 가로 눈금은 해가 바뀌는 첫 날짜마다 연도, 그런 날이 둘보다 적으면 달이 바뀌는 날마다 "YY-MM"이다. 10개가 넘으면 고르게 솎는다.
      - 눈금 글은 `aria-hidden`이고, SVG `aria-label`에 종목별 최대 낙폭과 날짜를 다 적는다: "평가금 최고점 대비 낙폭 그래프. QQQ 최대 −24.9% (2026-11-20), …". 낙폭이 없는 종목은 "QQQ 낙폭 없음"이다.
      - 요약 탭 그래프의 범례 숨김·보는 기간과 상관없이 늘 전체 기간·모든 종목이다.
    - 흔들림 상자 아래는 두 줄 격자(상자 폭 560px 이상이면 둘씩, 좁으면 하나씩)다. 순서는 시안처럼 연도별 결과 → 수익은 어디서 왔나 → 달마다 얼마나 움직였나 → 얼마에 샀나다. 수익 상자가 없으면(아래) 그 자리를 비우지 않고 당긴다.
    - 연도별 결과 표 (9-2, `analysis.years`). 행은 모든 종목의 연도를 합쳐 오름차순, 열은 연도 → 누적 투자금 → 종목마다(견본·코드)다.
      - 칸: 그해 누적 수익률(굵게, 손익 색·기호, 소수 1자리)과 아래 작은 회색 글 "주가 +54.7%"(`price_change_pct`, 종목 통화). `price_change_pct`가 `null`이면 "주가 —", 그해 값이 없는 종목은 "—"다.
      - 누적 투자금: 그해 마지막 거래일까지의 투자금이다. `buys` 가운데 그해까지(연도 ≤ 그해)의 마지막 줄 `invested`를 쓴다. 그해에 매수가 없으면 앞 해 값과 같다. 모든 줄·모든 종목의 값이 같으면 열 하나로 두고, 하나라도 다르면(상장일·거래소가 다름) 그 열을 빼고 종목 칸 아래에 "투자금 2,600만원"으로 적는다 (결정 d66. 표 모양이 줄마다 바뀌지 않게 표 전체로 정한다).
      - 표 위 글: "그해 마지막 거래일 기준 누적 수익률. 아래 작은 글씨는 그해 주가 등락(달러)". 괄호는 종목 통화 이름이고, 결과 종목 통화가 여럿이면 "종목 통화"다.
      - 표 아래: "2026년은 11-23까지." 마지막 연도에 끝나는 `data_through`(월-일)다. 종목마다 다르면 "2026년은 QQQ 11-23, 005930.KS 11-24까지."로 쓴다. 그해가 다 찼는지는 거래일 달력 없이 알 수 없어 늘 붙인다. 시안의 해설 문장("2022년은 주가가 … 반등을 크게 받았습니다")은 넣지 않는다 (결정 d62).
    - 수익은 어디서 왔나 (9-4, `summary.price_effect`·`fx_effect`·`profit`·`avg_buy_fx`). 종목 통화가 투자 통화와 다른 종목만 줄로 둔다. 그런 종목이 없으면(달러로 달러 종목만 샀을 때 등) 상자를 통째로 뺀다.
      - 위 글: "원화 손익 = 주가 효과(달러로 번 돈 × 지금 환율) + 환율 효과(산 달러를 지금 환율로 바꾼 값 − 넣은 원화)". 원화는 투자 통화, 달러는 줄에 든 종목 통화 이름이고 여럿이면 "종목 통화"다.
      - 줄: 견본·코드 | 막대(종목 색, 길이는 |손익| ÷ 줄 가운데 가장 큰 |손익|)와 그 아래 "주가 효과 +6,581만원 · 환율 효과 −75만원" | 손익 "+6,506만원". 손익은 `summary.profit`이라 두 효과의 합과 1원 다를 수 있다 (4절). 세 값 모두 화면에 보이는 값의 부호로 손익 색을 칠한다 (시안은 환율 효과만 손실 색, 손익은 이익 색 고정).
      - 아래 상자(틀에 숫자를 넣은 사실 문장, 결정 d62): 줄이 둘 이상이고 환율 효과의 보이는 값·종목 통화·매수일(횟수·첫날·끝날)이 모두 같으면 "**환율 효과는 4개 종목 모두 −75만원으로 같습니다.** 같은 날 같은 원화를 달러로 바꿨기 때문입니다." 그다음 "60번 평균 매수 환율은 1,352.57원(가장 쌀 때 1,182.86원 2021-12-01, 가장 비쌀 때 1,548.61원 2026-07-01)이고, 평가 환율 1,344.16원이 그보다 낮습니다." 60은 매수일 수(`summary.buys`, 쉰 날도 그날 환전하므로 센다, 9-4)이고, 가장 쌀 때·비쌀 때는 `buys[].fx`에서 고른다 (같으면 앞 날짜). 평가 환율이 보이는 값으로 같으면 "그와 같습니다", 높으면 "그보다 높습니다"다. 이 문장이 종목마다 다르면 줄마다 "QQQ 60번 평균 …"으로 쓴다. 환율 단위는 투자 통화가 원화일 때만 "원"을 붙인다.
      - 환율 변동 제외 (F-24, 응답 `params.include_fx`가 `false`, 결정 d74·d75): `fx_effect`가 0, `price_effect`가 손익이다. 위 글은 "원화 손익 = 주가 효과(달러로 번 돈 × 평균 매수 환율) + 환율 효과(환율 변동 제외라 0)"이고, 아래 상자는 "**환율 변동 제외로 계산했습니다.** 통화가 다른 종목은 지금 환율 대신 그날까지의 평균 매수 환율로 평가해 환율 효과가 0입니다." 뒤에 비교 없는 "60번 평균 매수 환율은 1,352.57원(가장 쌀 때 …, 가장 비쌀 때 …)입니다."를 쓴다 (환율 효과가 같은 이유와 평가 환율 비교는 끔에서 틀린 말이라 뺀다. 평균 매수 환율은 끔에서도 그대로이고 평가에 쓴 값이다). `include_fx`가 없는 응답은 켬이다.
    - 달마다 얼마나 움직였나 (9-3, `analysis.months`). 고른 종목 하나의 히트맵이다.
      - 종목 고르기: 결과 종목을 모두 `.seg` 버튼(`aria-pressed`)으로 두고 처음은 첫 종목이다. 종목이 하나면 버튼을 두지 않는다 (매수 내역과 같다). 고르면 이 상자만 다시 그린다. 다시 계산하면 첫 종목으로 돌아간다.
      - 위 글: "월말 종가 × 환율 기준 월 수익률 (원화)". 괄호는 투자 통화 이름이다. 고른 종목 통화가 투자 통화와 같으면 환율이 곱해지지 않으므로 "월말 종가 기준 월 수익률 (달러)"로 쓴다.
      - 히트맵은 표(`<table>`, 행 머리 연도·열 머리 1~12월)다. 행은 `months`에 나오는 연도, 칸은 월 수익률(소수 1자리, 기호)이고 데이터가 없는 달은 빈칸이다. 바탕은 손익 색을 옅게 깔고 |값|에 따라 진해지다 25%에서 멈춘다. 라이트는 시안대로 8% + 55% × min(|값|, 25) ÷ 25이고, 다크는 가장 진한 칸에서도 글자 대비 4.5:1을 지키게 더 옅다 (토큰 `--hm-lo`·`--hm-span`). 글자는 본문 색이고, 화면에 0.0%로 보이는 칸은 색이 없다. 색만으로 알리지 않는다 (기호와 글자).
      - 아래 세 칸: 오른 달 / 내린 달 "36달 / 23달"(0보다 큰 달 / 0보다 작은 달, 응답 값 기준), 가장 크게 오른 달 "2026-04 +30.4%", 가장 크게 내린 달 "2022-12 −22.3%". 같은 값이면 앞의 달이고, 오른(내린) 달이 하나도 없으면 "없음"이다.
      - 끝난 달이 없으면(`months`가 빔) 표와 세 칸 대신 "끝난 달이 없어 월별 수익률이 없습니다"를 보인다.
    - 얼마에 샀나 (9-1, `buys[].price`, `analysis.buys_below_*`). 고른 종목 하나의 매수 가격 분포다. 종목 고르기는 달마다 상자와 같다 (따로 고른다).

- 주소 쿼리 (F-09). 잘못된 값은 버리고 기본값을 쓴다. 쿼리에 `s`가 있으면 열자마자 계산한다.

  | 키 | 뜻 | 예 |
  |---|---|---|
  | `s` | 종목 코드, 쉼표로 (8개까지) | `s=QQQ,QLD` |
  | `from`, `to` | 시작일, 끝날짜. "전체"는 `from=1970-01-02` | `from=2021-11-25` |
  | `freq` | `daily`, `weekly`, `monthly` | `freq=monthly` |
  | `day` | 매주는 0(월)~4(금), 매월은 1~31(31 = 말일). 매일이면 없음 | `day=1` |
  | `amt` | 회당 금액 (투자 통화) | `amt=2000000` |
  | `cur` | `KRW`, `USD` | `cur=KRW` |
  | `rule` | 매수 규칙(v2, F-17): `ma_dip`(이평선 아래 2배·위 절반), `ma_hot`(과열 때 절반), `switch`(레버리지 전환). 기본(`none`)이면 없음. 그 밖의 값(`lump_sum` 등)은 버린다. 이평선 기간·기준 종목은 늘 200일·QQQ라 키가 없다 (결정 d43) | `rule=ma_dip` |
  | `frac` | 정수 주만이면 `0`. 소수점 매수(기본)면 없음 | `frac=0` |
  | `fee` | 수수료 %. 0이면 없음 | `fee=0.25` |
  | `tax` | 해외주식 양도세 어림(v2, F-20)을 켜면 `1`. 꺼짐(기본)이면 없음. `1`이 아닌 값은 버린다 | `tax=1` |
  | `tab` | 결과 탭 (v2, F-11): `analysis`(분석), `strategy`(전략 비교), `buys`(매수 내역). 요약(기본)이면 없음. 계산에는 쓰지 않는다 | `tab=buys` |

  키는 조건 패널 순서로 쓰고 `tab`은 맨 뒤다: `s`·`from`·`to`·`freq`·`day`·`amt`·`cur`·`rule`·`frac`·`fee`·`tax`·`tab`. 예: `/?s=QLD&from=2021-11-25&to=2026-11-24&freq=monthly&day=1&amt=2000000&cur=KRW&rule=ma_dip&tax=1&tab=buys`.

  탭만 바꿀 때는 다시 계산하지 않고, 마지막으로 계산한 조건의 주소에서 `tab`만 바꾼다 (`history.replaceState`). 폼에서 바꾸고 아직 계산하지 않은 값은 주소에 들어가지 않는다.
