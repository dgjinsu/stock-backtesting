# 상세 설계

[아키텍처](3_아키텍처.md)에서 정한 구조의 세부 규격이다. 계산 공식은 [계산 규칙](2_계산규칙.md)에 있다.

## 1. 데이터 출처: Yahoo Finance (비공식)

### 일별 종가
```
GET https://query1.finance.yahoo.com/v8/finance/chart/{symbol}
    ?period1=0&period2={지금+1일 유닉스초}&interval=1d&events=split
헤더: User-Agent: Mozilla/5.0   (없으면 막힌다)
```
- `period1=0`이면 상장 이후 전체가 **일봉으로** 온다 (QQQ 6,971일, 2026-11-24 확인).
- 응답에서 쓰는 것:
  - `meta.currency`, `meta.gmtoffset`, `meta.exchangeTimezoneName`, `meta.longName`/`shortName`
  - `timestamp[]`, `indicators.quote[0].close[]` (분할 반영 종가), `indicators.adjclose[0].adjclose[]` (배당까지 반영. 받아서 저장만 하고 계산에는 쓰지 않는다, 결정 d36)
  - `events.splits` (분할 날짜와 비율, 안내용)
- `close`가 `null`인 날은 건너뛴다. 날짜 변환은 [계산 규칙](2_계산규칙.md) 1절.
- 없는 종목은 HTTP 404 또는 `chart.result`가 비어 있다.
- 환율도 같은 주소다: `USDKRW=X`. `KRW=X`와 같은 데이터다.

### 검색
```
GET https://query1.finance.yahoo.com/v1/finance/search?q={검색어}&quotesCount=8&newsCount=0
```
- `quotes[]`의 `symbol`, `shortname`/`longname`, `exchDisp`, `quoteType`을 쓴다.
- `quoteType`이 EQUITY, ETF, INDEX, MUTUALFUND, CRYPTOCURRENCY인 것만 남긴다 (OPTION 등 제외).
- 한글 같은 검색어에는 HTTP 400 `"Invalid Search Query"`를 준다 (2026-11-25 확인). 본문의 `finance.error.description`이 이 문구일 때만 결과 없음으로 보고 `[]`를 돌려준다. 그 밖의 400·4xx·5xx는 503이다.
- 한글 이름은 못 찾는다. 코드와 영문 이름은 된다.

### 주의
- 공식 API가 아니다. 주소나 응답이 바뀌면 멈출 수 있고, 너무 자주 부르면 429로 막힌다.
- 이용약관상 개인 용도로 쓴다. 공개 서비스로 키우면 데이터 출처를 바꾼다 (예: Twelve Data, Alpha Vantage, 한국 종목은 증권사 Open API). 그래서 `market.py`는 "종목 코드 → 날짜·종가 목록"이라는 한 가지 함수로만 바깥에 보이게 한다.

## 2. 캐시 파일

`data/prices/{종목코드}.json`. 종목 코드를 대문자 그대로 파일 이름으로 쓴다 (`QLD.json`, `USDKRW=X.json`, `005930.KS.json`).

```json
{
  "symbol": "QLD",
  "name": "ProShares Ultra QQQ",
  "currency": "USD",
  "exchange_tz": "America/New_York",
  "fetched_at": 1795500000,
  "dates":    ["2006-06-21", "2006-06-22", "..."],
  "close":    [0.0, 0.0],
  "adjclose": [0.0, 0.0],
  "splits":   [["2025-11-20", "2:1"]]
}
```

- `dates`는 거래소 현지 날짜, 오름차순, 중복 없음. `close`(분할 반영)와 `adjclose`(배당까지 반영, 저장만 하고 계산에는 쓰지 않음)는 `dates`와 길이가 같다. 날짜마다 객체를 두지 않고 열마다 배열로 둔다. 엔진에는 `dates`·`close`를 그대로 넘긴다.
- `fetched_at`(유닉스초)이 6시간 안이면 다시 받지 않는다.
- **받을 때마다 그 종목 전체를 다시 받아서 파일을 통째로 바꾼다.** 분할이 생기면 Yahoo가 과거 종가를 전부 다시 계산하기 때문이다 ([아키텍처](3_아키텍처.md) 4절).
- 저장은 같은 폴더의 임시 파일에 다 쓴 뒤 `os.replace`로 바꿔치기한다. 쓰다가 죽어도 깨진 파일이 남지 않는다.
- 종목별 잠금을 읽을 때도 건다. 윈도우에서는 누가 파일을 열고 있으면 바꿔치기가 실패한다. 같은 종목을 동시에 두 번 받는 일도 막는다.
- 받기에 실패하면 저장된 값으로 계산하고, 응답에 `stale: true`와 마지막 날짜를 넣는다. 저장된 것도 없으면 그 종목만 오류로 돌려준다.
  - "받기 실패"에는 네트워크·HTTP 오류, 응답 모양이 예상과 다른 경우, 저장본이 있던 종목을 Yahoo가 갑자기 없다고 하는 경우(상장 폐지 등)가 모두 들어간다.
- 파일이 깨져서 읽히지 않으면 없는 것으로 보고 다시 받는다.

## 3. 계산 엔진 (`engine.py`)

입출력 없이 데이터만 받아 계산한다. 그래서 저장된 fixture로 바로 테스트할 수 있다.

```python
@dataclass
class Series:            # main.py _to_series가 market의 PriceHistory로 만든다
    symbol: str
    currency: str
    dates: list[date]    # 오름차순, 중복 없음
    close: list[float]
    exchange_tz: str = ""   # 거래소 시간대 (Yahoo exchangeTimezoneName). 모르면 "". 같은지만 본다

@dataclass
class Params:
    start: date; end: date
    freq: Literal["daily", "weekly", "monthly"]
    anchor: int | None   # weekly 0~4(월~금), monthly 1~31
    amount: float        # 투자 통화
    currency: str        # "KRW" | "USD"
    fractional: bool = True
    fee: float = 0.0     # 0.0025 = 0.25%

def buy_days(dates, start, end, freq, anchor) -> list[date]
def simulate(asset: Series, fx: Series | None, p: Params) -> SimResult
    # SimResult: summary(Summary), buys(list[BuyRow]), daily(list[DailyRow]) — 모두 dataclass
def xirr(flows: list[tuple[date, float]]) -> float | None
def rate_on(fx: Series | None, day: date) -> float
    # 환율 (3절): day 당일 또는 그 이전 마지막 종가. fx가 None이면 1, 이전 값이 없으면 EngineError
    # 9-5 양도세 환율(USDKRW=X)도 main이 이 함수로 찾는다
def build_chart(results: dict[str, SimResult], max_points=1000) -> Chart
    # 모든 종목 거래일을 합친 날짜축, 없는 날은 직전 값, 최대 max_points로 줄이기
    # Chart: dates, series(종목별 ChartSeries: value·invested·return_pct·price·avg_cost·drawdown),
    # total_days(줄이기 전 날짜 수). drawdown은 9-1 평가금 낙폭(%)이고 analyze와 같은 함수로 계산한다
def analyze(result: SimResult, asset: Series, fx: Series | None, end: date, *, tax_fx: float) -> Analysis
    # v2 지표 (계산 규칙 9-1~9-5): 낙폭, 원금 아래, 연도별, 월별, 수익 분해, 양도세
    # asset은 끝날짜로 자르지 않은 전체 데이터다 (9-3 끝난 달은 2절 매수일처럼 데이터 마지막 날을 본다)
    # tax_fx는 투자 통화 1단위의 원화 값 (원화 투자면 1, 달러 투자면 끝날짜 당일 또는 그 이전 마지막
    # USDKRW=X 종가, 9-5). 기본값 없음, 0 이하면 ValueError
def same_exchange(a: Series, b: Series) -> bool
    # exchange_tz가 둘 다 비어 있지 않고 같을 때만 True (9-6, 결정 d29). API의 switch_ref.basis도 이것으로 정한다
def simulate_rule(asset, fx, ref: Series | None, p: Params, rule, ma_days=200) -> StrategyResult
    # 같은 예산 전략 (9-6): none·ma_dip·ma_hot·switch·lump_sum. ref는 레버리지 전환의 기준 종목. 소수점 매수
    # switch: same_exchange(asset, ref)면 매수일의 종가·이평선을 보고,
    # 아니면(다르거나 하나라도 비어 있으면) 매수일보다 앞선 마지막 거래일 기준 (9-6)
def build_strategy_chart(results: Sequence[StrategyResult], max_points=1000) -> StrategyChart
    # 전략별 평가금 추이 (F-15). 날짜축은 전략의 daily 날짜(같은 조건으로 계산한 전략은 모두 같다). 줄이기는 build_chart와 같은 규칙
    # StrategyChart: dates, series(전략별 value·invested·return_pct, 빈 값 없음), total_days
    # 날짜축이 다르거나 같은 전략이 두 번이면 ValueError
def anchor_sweep(asset, fx, p) -> dict[int, float | None]   # 매월 1~28일·말일의 평단가 (9-7)
def start_sweep(asset, fx, p) -> dict[str, float]            # 각 달 1일 시작의 수익률 (9-7)
```

- `tests/reference_calc.py`의 함수 구조를 그대로 가져와도 된다. 다만 `simulate`는 매수일만이 아니라 거래일마다 평가금·투자금·수익률(`daily`)도 만든다.
- XIRR은 뉴턴법으로 풀고, 수렴하지 않으면 이분법(−99.99% ~ +10,000%)으로 넘어간다. 해가 없거나 구간 밖이면 `None`.
- 계산할 수 없는 데이터(기간 안 매수일 없음, 환율 없음)는 `EngineError`, 입력 계약 위반(금액 0, 통화와 환율 인자가 안 맞음)은 `ValueError`다. API는 앞의 것을 종목별 `errors`로 돌려준다.
- 그래프용으로 줄일 때는 일정 간격으로 고르되 **첫날, 마지막 날, 최고·최저 수익률 날짜는 꼭 남긴다.** 종목 그래프는 종목마다 평가금 최대 낙폭 날짜도 남긴다(낙폭 그래프의 가장 낮은 점이 `summary.max_drawdown`과 같다). 전략 그래프는 전략마다 최고·최저 수익률 날짜를 남긴다.

### `POST /api/backtest`
요청
```json
{
  "symbols": ["QQQ", "QLD"],
  "start": "2021-11-25",
  "end": "2026-11-24",
  "freq": "monthly",
  "anchor": 1,
  "amount": 2000000,
  "currency": "KRW",
  "fractional": true,
  "fee_pct": 0,
  "tax": true
}
```
검사: 종목 1~8개, 형식 `^[A-Za-z0-9.\-=^]{1,20}$`, `start < end ≤ 오늘`, `amount > 0`, `fee_pct` 0~10, freq에 맞는 anchor 범위, `tax`는 true/false(기본 false, F-20 양도세 어림). 어기면 422와 항목별 메시지.

응답 (QLD, 매월 1일 200만원, 2021-11-25 ~ 2026-11-24, `tax: true`, fixture 기준 실제 값. v2 지표는 `expected.json`의 `v2.metrics`와 같다)

- 종목 하나가 실패해도 나머지 결과는 돌려준다 (`errors`에 따로). 환율을 받지 못한 종목도 그 종목만 실패한다 ("USDKRW=X 환율을 받지 못해 계산하지 못했습니다.").
- `notes`는 시작일 뒤의 분할이다. 끝날짜 뒤의 분할도 가격·수량에 반영돼 있어서 같이 적는다.
- `tax`가 켜진 달러 투자에서 양도세용 `USDKRW=X`를 받지 못하면, 원화가 아닌 종목은 모두 그 종목 오류다 (결정 d40). 메시지는 환율 실패와 같다.
- `stale`이면 저장본(종목이나 환율. 양도세용 `USDKRW=X`도 포함)으로 계산했고, `data_through`는 평가에 쓴 마지막 거래일이다. `listed_from`은 상장일이 시작일보다 늦을 때만 그 첫 거래일이다.
- 엔진에는 끝날짜로 자르지 않은 전체 데이터를 넘긴다 (결정 d32. 9-3 끝난 달은 데이터 마지막 날을 본다).
- `summary`의 v2 지표는 [계산 규칙](2_계산규칙.md) 9-1·9-4·9-5다. 금액은 투자 통화, 비율은 %다.
  - 값이 없을 때 (결정 d25): 낙폭이 없으면 `max_drawdown`, 원금 아래였던 적이 없으면 `longest_underwater`·`last_underwater`가 `null`이다. 끝까지 원금 위로 못 올라왔으면 `recovered`가 `null`이다. 투자 통화와 종목 통화가 같으면 `avg_buy_fx`가 `null`이고 `fx_effect`는 0이다.
  - `tax: false`면 `tax`·`profit_after_tax`가 `null`이다. 한국 종목은 0이다. 달러 투자면 끝날짜 당일 또는 그 이전 마지막 `USDKRW=X` 종가로 원화 공제를 계산한다 (9-5). 이 환율은 요청 하나에 한 번만 받는다.
  - 반올림 뒤라 `price_effect + fx_effect`가 `profit`과 1원 다를 수 있다.
- `analysis`는 9-1·9-2·9-3이다. `years` 키는 "YYYY", `months` 키는 "YYYY-MM"이고 둘 다 오름차순이다. `months` 값은 %이고 `/api/strategy`의 `start_sweep`과 같은 모양이다. 매수 가격 목록은 따로 두지 않는다. 같은 응답의 `buys[].price`(줄이지 않은 전체)를 쓴다.
- `chart.series` 값은 그 종목 첫 매수 전 날짜에서 `null`이다. `value`·`invested`는 투자 통화, `price`·`avg_cost`는 종목 통화, `drawdown`은 그날 평가금 낙폭(%)이다.
- 저장본으로 4종목(QQQ·QLD·TQQQ·SOXL) 5년 매일 `tax: true` 요청 하나는 개발 PC에서 약 0.05초, 응답은 약 970KB다. 기준은 1초다 (비기능 "속도").
- `chart.total_days`는 줄이기 전 날짜 수다. `dates`보다 많으면 화면이 그래프 아래에 "기간이 길어 그래프는 2,513일 중 998점만 골라 그렸습니다…"처럼 알린다 (F-07).
- `buys`는 줄이지 않는다. 매일 매수 10년이면 종목당 약 2,500줄이다.
- 숫자 반올림은 [계산 규칙](2_계산규칙.md) 5절 끝의 "응답 자리수"를 따른다.

오류 응답
```json
// 422 입력 오류: 항목별로
{"detail": [{"field": "anchor", "message": "매주 매수 요일은 0(월)~4(금) 중 하나입니다"},
            {"field": "start", "message": "시작일은 끝날짜보다 앞이어야 합니다"}]}
// 503 검색 실패
{"detail": "종목을 검색하지 못했습니다. 잠시 뒤 다시 시도해 주세요."}
```
- "오늘"은 한국 날짜다.
- 검사는 두 단계다. 한 항목만 보고 알 수 있는 오류(종목 개수·형식, 금액, 수수료, 날짜 형식)가 있으면 그 오류만 먼저 돌려준다. 그게 없을 때 항목끼리 맞추는 오류(기준일, 시작일 ≥ 끝날짜, 끝날짜 > 오늘)를 모아서 돌려준다.

### `POST /api/strategy`
전략 비교(F-15)용이다. 종목 하나를 같은 예산 전략 5개로 계산하고([계산 규칙](2_계산규칙.md) 9-6), 전략별 평가금 추이와 매수일·시작 시점 바꿔 보기(9-7)도 같이 돌려준다. 요청이 무거워서 `/api/backtest`와 따로 둔다.

요청: 조건 항목(`start`·`end`·`freq`·`anchor`·`amount`·`currency`·`fractional`·`fee_pct`)은 `/api/backtest`와 같고, 종목 목록 대신 아래 셋이 있다.
```json
{
  "symbol": "QLD",
  "start": "2021-11-25", "end": "2026-11-24",
  "freq": "monthly", "anchor": 1, "amount": 2000000, "currency": "KRW",
  "fractional": true, "fee_pct": 0,
  "ma_days": 200,
  "switch_ref": "QQQ"
}
```
검사: 조건 항목은 `/api/backtest`와 같다. `symbol`·`switch_ref`는 종목 코드 형식, `ma_days`는 20·60·120·200 중 하나(기본 200), `switch_ref` 기본은 QQQ. 오류 모양과 두 단계 검사도 같다.

응답 (위 요청, fixture 기준 실제 값. `expected.json`의 `v2`와 같다)

- `strategies`의 키와 순서는 `engine.RULES`(none·ma_dip·ma_hot·switch·lump_sum)와 같다. 안쪽 이름은 `expected.json` `v2.strategies`와 같고 `invested`가 하나 더 있다. 일시금을 포함한 5개 모두 같은 총액이다 (9-6).
- 금액(`value`·`invested`·`leftover_cash_invest`)은 투자 통화, `avg_cost_asset`은 종목 통화다. `rule_days`는 규칙이 걸린 매수일 수다 (이평선 아래·과열·쉰 날). 반올림은 [계산 규칙](2_계산규칙.md) 5절 끝을 따른다.
- 전략은 소수점 매수로 계산한다. `fractional: false`여도 값이 같다 (결정 d28).
- 엔진에는 시작일·끝날짜로 자르지 않은 전체 데이터를 넘긴다. 이평선은 시작일 이전 주가를 쓰고(9-6), 진행 중인 달은 데이터 마지막 날로 판정한다(2절).
- 기준 종목은 환율 없이 받는다. 기준 종목이 종목과 같으면 한 번만 받는다.
- `switch_ref.basis`는 레버리지 전환이 기준 종목의 어느 날 종가·이평선을 봤는지다 (결정 d29). `same_day`는 같은 거래소라 매수일 것을, `previous_day`는 다른 거래소이거나 시간대를 몰라 매수일보다 앞선 마지막 거래일 것을 봤다는 뜻이다.
- `stale`은 종목이나 환율을 저장본으로 계산했다는 뜻이고, 기준 종목이 저장본이면 `switch_ref.stale`에 따로 적는다. `notes`·`data_through`·`listed_from`은 `/api/backtest`와 같은 뜻이다.
- `chart`는 전략별 평가금 추이다.
  - 날짜축은 첫 매수일부터 `data_through`까지의 거래일이다. 전략이 모두 같은 날짜를 써서 `null`이 없다.
  - `series` 키는 계산한 전략만 `engine.RULES` 순서로 들어간다. `value`·`invested`는 투자 통화, `return_pct`는 %다.
  - 줄이기와 `total_days`는 `/api/backtest`의 `chart`와 같다. 최고·최저 수익률 날짜는 전략마다 남긴다.
- `anchor_sweep`은 매월 1~28일과 말일(키 `"31"`)에 샀을 때의 평단가다(종목 통화, 소수 4자리). 키는 29개이고, 위 예는 그중 일부다. `start_sweep` 예(54개 중 일부)도 같다.
  - 요청 주기와 상관없이 매월로 계산한다 (9-7, 결정 d27).
  - 그 기준일로는 기간 안에 매수일이 없거나, 정수 주만 살 때 한 주도 사지 못했으면(평단가가 없음) `null`이다.
- `start_sweep`은 시작일을 각 달 1일로 바꿔 끝날짜까지 계산한 수익률(%)이다. 키는 `"YYYY-MM"` 오름차순이다.
  - 범위는 1일이 시작일 당일이나 그 뒤인 달부터, 끝날짜가 든 달의 6개월 전 달까지다. 상장 달보다 앞선 달은 뺀다.
  - 시작할 달이 없으면 `{}`다.
- 두 바꿔 보기는 2·4절 그대로 요청의 조건(수수료, `fractional`)으로 계산하고, 기준 종목과 `ma_days`는 쓰지 않는다. 전략은 소수점 매수로만 계산하므로(결정 d28) `fractional: false`면 같은 응답 안에서 계산 방식이 다르다. 그 대신 매월 요청이고 기준일이 1~28일이나 31일이면, 그 기준일의 `anchor_sweep` 값이 `/api/backtest` 평단가와 같다. 기준일 29·30인 요청과 매일·매주 요청은 `anchor_sweep`에 지금 조건의 점이 없다 (화면 표시는 13단계에서 정한다).
- 응답은 그래프 때문에 5년 매일이면 약 160KB다. 저장본으로 5년 매일 요청 하나는 개발 PC에서 0.2~0.26초다. 2초 기준은 요청 하나마다 잰다 (결정 d30).

오류
- 종목이나 환율을 못 받았거나 기간 안에 매수일이 없으면 200, `result: null`, `errors`에 그 종목을 적는다. 메시지는 `/api/backtest`와 같다.
- 기준 종목만 못 받으면 레버리지 전환만 뺀다: `strategies.switch: null`, `switch_ref: null`, `chart.series`에 switch 키 없음, `errors`에 기준 종목. 나머지 4개 전략과 두 바꿔 보기는 그대로 돌려준다 (결정 d31).
- 바꿔 보기에서 계산할 수 없는 데이터(다른 기준일이 환율 데이터 시작보다 먼저 사는 경우)도 `result: null`과 종목 오류다.
- 둘 다 실패하면 `errors`에 종목 줄이 먼저, 기준 종목 줄이 그다음이다.

- 조건 패널은 왼쪽 고정폭(320 ~ 360px), 결과는 나머지. 1024px 폭에서도 둘이 나란히 보인다.
- 상태: 처음(입력만) → 계산 중(버튼 잠금, 종목별 진행) → 결과 / 일부 오류 / 전체 오류. 시안 "v1 · 상태" 보드에 모두 그려 두었다.
- v2 결과 탭 (F-11). 위에서부터 결과 머리 줄(조건 한 줄·링크 복사·CSV) → 알림 → 탭 `[요약][분석][전략 비교][매수 내역]` → 탭 내용 → 고정 안내. 머리 줄·알림·안내는 어느 탭에서나 보인다.
  - 요약: 한눈에 요약 → 카드 → 비교 표 → 그래프. 매수 내역: 매수 내역 표와 CSV 내려받기. 분석(F-14)·전략 비교(F-15)는 13단계에서 채우고, 그때까지 "다음 단계에서 채웁니다" 안내만 둔다 (결정 d41).
  - 한눈에 요약 (F-12): 정해진 틀에 숫자를 넣은 문장 한 단락과 하이라이트 4칸(가장 높은 XIRR, 현재가가 평단가의 몇 배, 가장 깊은 손실, 원금 아래였던 날이 가장 적음. 칸마다 종목 견본·코드·값·날짜나 비율). 문구 틀과 고르는 규칙은 `web/insights.js` 한 곳에 둔다 (결정 d42·d43). 같은 값이면 결과 순서가 앞인 종목, XIRR이 `null`인 종목은 XIRR 1위에서 뺀다. 화면 폭이 좁으면(1024px) 하이라이트는 2×2로 놓는다.
  - 탭은 WAI-ARIA 탭 패턴이다 (`tablist`·`tab`·`tabpanel`, `aria-selected`). ←/→로 옮기면 바로 그 탭을 열고, Home/End는 처음·끝 탭이다. 탭을 바꿔도 다시 계산하지 않는다 (네 탭을 한 번에 그려 두고 보이고 숨긴다).
  - 처음 계산은 요약 탭으로 연다. 주소에 `s`와 `tab`이 있으면 계산이 끝난 뒤 그 탭을 연다. 다시 계산하면 보던 탭을 그대로 둔다.
  - 요약이 아닌 탭에서는 왼쪽 조건 패널을 결과 위 한 줄로 접고 결과가 전체 폭을 쓴다. 접힌 줄은 시안 v2의 분석·매수 내역 보드처럼 `조건 · ─ QQQ ╌ QLD · 2021-11-25 ~ 2026-11-24 · 매월 1일 · 종목마다 200만원 · 원화 [조건 펼치기]`이고, 폼이 아니라 보이는 결과를 계산한 조건으로 적는다 (정수 주·수수료는 기본값이 아닐 때만).
  - "조건 펼치기"(`aria-expanded`)를 누르면 그 탭에 머문 채 패널이 열리고, 같은 버튼이 "조건 접기"로 바뀐다. 탭을 바꾸면 다시 요약은 펼침, 그 밖은 접힘이다. 접힘 상태는 주소에 담지 않는다.
- 그래프 색은 종목 순서대로 아래 8색, 선 모양도 종목마다 다르게 (실선, 긴 점선, 짧은 점선, …). 투자금과 평단가는 회색 계단선.
  - 투자금 선은 종목들의 투자금이 같으면 하나, 상장일·매수일이 달라 다르면 종목마다 그 종목의 선 모양으로 그린다. 범례 견본도 같은 선 모양이다.
  - 주가·평단가 그래프는 주가가 평단가 위인 구간을 초록, 아래를 빨강으로 옅게 채운다 (색만으로 뜻을 전하지 않게 그래프 아래에 글로도 적는다).
  - x축 눈금은 기간이 1년보다 길면 연-월, 짧으면 날짜 전부 (짧은 기간에 같은 달이 여러 번 찍히지 않게).
  - CSV 열: 종목, 통화(종목 통화), 회차, 날짜, 종가, 환율, 산 수량, 누적 수량, 누적 평단가, 투자 통화 평단가, 누적 투자금. UTF-8 BOM, 줄 끝 CRLF.

- 색은 종목에 붙는다. 종목을 빼도 남은 종목 색이 바뀌지 않는다.
- 주소 쿼리 (F-09). 잘못된 값은 버리고 기본값을 쓴다. 쿼리에 `s`가 있으면 열자마자 계산한다.

  | 키 | 뜻 | 예 |
  |---|---|---|
  | `s` | 종목 코드, 쉼표로 (8개까지) | `s=QQQ,QLD` |

  | `freq` | `daily`, `weekly`, `monthly` | `freq=monthly` |
  | `day` | 매주는 0(월)~4(금), 매월은 1~31(31 = 말일). 매일이면 없음 | `day=1` |
  | `amt` | 회당 금액 (투자 통화) | `amt=2000000` |
  | `cur` | `KRW`, `USD` | `cur=KRW` |
  | `frac` | 정수 주만이면 `0`. 소수점 매수(기본)면 없음 | `frac=0` |
  | `fee` | 수수료 %. 0이면 없음 | `fee=0.25` |
  | `tab` | 결과 탭 (v2, F-11): `analysis`(분석), `strategy`(전략 비교), `buys`(매수 내역). 요약(기본)이면 없음. 계산에는 쓰지 않는다 | `tab=buys` |

  탭만 바꿀 때는 다시 계산하지 않고, 마지막으로 계산한 조건의 주소에서 `tab`만 바꾼다 (`history.replaceState`). 폼에서 바꾸고 아직 계산하지 않은 값은 주소에 들어가지 않는다.

- 평가금 그래프는 레버리지 종목 하나가 튀면 나머지가 납작해진다 (SOXL 매월 200만원이 2026-06-22에 약 15억 8천만원). 그래서 로그 축 버튼과 수익률(%) 그래프를 둔다. v2에서는 범례로 종목을 숨기면 세로축을 다시 잡는다.
- 손익 색은 미국식이다: 이익 초록(라이트 #0B7A47, 다크 #43C08A), 손실 빨강(라이트 #C42B2B, 다크 #F27A74). 둘 다 흰·검정 배경에서 글자 대비 4.5:1 이상.
- 글꼴은 IBM Plex Sans KR, 숫자는 고정폭 숫자(tabular-nums)로 맞춘다.
