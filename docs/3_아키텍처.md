# 아키텍처

무슨 언어로 만들고, 어떤 덩어리로 나누고, 데이터를 어디에 두는지 정한다. 결정마다 이유와 "언제 다시 볼지"를 같이 적는다.
세부 규격(Yahoo 주소, 캐시 파일 형식, API 요청·응답, 화면)은 [상세 설계](4_상세설계.md)에 있다.

## 1. 한눈에

```
web/ (브라우저)
  │  POST /api/backtest, POST /api/strategy, GET /api/search
  ▼
src/main.py ............ HTTP, 입력 검사, 이어 붙이기
  ├─▶ src/engine.py .... 계산만 (입출력 없음)
  └─▶ src/market.py .... 주가 받기·저장, 종목 검색
        ├─▶ Yahoo Finance
        └─▶ data/prices/{종목}.json (캐시)
```

- 계산은 서버(파이썬)에서 한다. 브라우저는 입력을 받고 결과를 그리기만 한다.
- 브라우저는 Yahoo를 직접 부르지 않는다. Yahoo가 브라우저 요청을 CORS로 막는다.
- 로그인도, 서버에 남는 사용자 데이터도 없다. 조건은 URL에 담는다 (F-09).

"계산하기"를 한 번 누르면:

1. 화면이 조건을 URL에 담고 `POST /api/backtest`를 부른다.
2. `main.py`가 입력을 검사한다. 틀리면 422와 항목별 메시지를 돌려준다.
3. 종목마다(환율 `USDKRW=X` 포함) `market.get_series`로 주가를 가져온다. 저장본이 6시간 안이면 파일에서, 아니면 Yahoo에서 받는다. Yahoo는 동시에 2개까지만 부른다.
4. `engine.simulate`(매수 규칙이면 `engine.simulate_with_rule`)가 종목마다 계산하고(v2 지표는 `engine.analyze`), `engine.build_chart`가 그래프용 날짜축을 맞춘다.
5. 결과와 실패한 종목 목록을 한 번에 돌려주면 화면이 카드·표·그래프를 그린다.

전략 비교 탭(F-15)은 탭을 열거나 종목·이평선을 고를 때 종목 하나로 `POST /api/strategy`를 따로 부른다. 같은 결과 안에서는 (종목, 이평선)마다 응답을 저장해 두고 다시 부르지 않는다.

## 2. 언어와 기술 (확정 2026-11-24)

| 부분 | 쓰는 것 | 이유 |
|---|---|---|
| 서버·계산 | Python 3.12 이상 (내 PC는 3.13) | 계산 기준인 `tests/reference_calc.py`가 파이썬이라 엔진과 나란히 놓고 비교할 수 있다. 다른 토이 프로젝트(기안 자동화, 용아맥 알리미)도 파이썬이다 |
| 웹 서버 | FastAPI + uvicorn | 요청·응답 검사(pydantic)와 API 문서(`/docs`)가 저절로 생긴다. 비동기라 여러 종목을 동시에 받기 쉽다 |
| 바깥 요청 | httpx | 타임아웃·비동기 요청이 쉽고, gzip 응답을 알아서 푼다 |
| 저장 | 종목마다 JSON 파일 하나 | 4절 |
| 화면 | HTML + CSS + 바닐라 JS (ES 모듈) | 화면이 하나라 빌드 도구가 필요 없다. 고치고 새로고침하면 끝 |
| 그래프 | Chart.js 4 (4.5.1, cdnjs에서 버전 고정·SRI로 불러온다) | 선 그래프, 툴팁, 로그 축이 기본으로 있다. 못 불러오면 그래프 자리에만 안내가 나오고 숫자 결과는 그대로다 |
| 테스트 | pytest | `expected.json` 기준값과 비교 |
| 코드 확인 | ruff (린트·포맷), mypy (타입) | 도구 둘로 빠르게 본다. 로컬과 CI가 같은 `scripts/check.py`를 돌린다 |
| 실행 | `실행.bat` (로컬), Docker (배포) | 5절 |

실행에 쓰는 라이브러리는 `fastapi`, `uvicorn`, `httpx` 세 개로 `requirements.txt`에, 개발 도구(`pytest`, `ruff`, `mypy`)는 `requirements-dev.txt`에 버전을 고정한다. 배포 이미지에는 앞의 것만 들어간다.

### 고르지 않은 것

| 후보 | 안 고른 이유 | 다시 볼 때 |
|---|---|---|
| Java + Spring Boot | 회사에서 쓰는 주력이지만 화면 하나·API 둘에는 뼈대가 크다. 무료 서버(메모리 512MB, CPU 0.1개)에서 JVM은 빠듯하고 켜지는 데 오래 걸린다 | Spring 경험을 보여 주는 게 목적이 될 때. 엔진은 `expected.json`으로 다시 검증하면 된다 |
| TypeScript + Next.js | 언어 하나로 끝나고 Vercel 무료 배포가 쉽지만, 엔진을 TS로 다시 짜야 한다 | 배포 뒤 콜드스타트가 거슬려서 계산을 브라우저로 옮기고 싶을 때 |
| Streamlit | 가장 빨리 만들지만 화면 배치를 마음대로 못 하고, URL 공유와 휴대폰 화면이 약하다 | |
| React + Vite | 화면 하나에 빌드 도구는 과하다 | 화면이 여러 개로 늘 때 |
| SQLite | 4절 | 4절 |
| numpy·pandas | 순수 파이썬으로 충분하다. XIRR을 뉴턴법으로 풀면 4종목 5년 매일 매수가 0.01초다 (참고 스크립트의 이분법 200회로는 0.26초) | 계산이 1초를 넘을 때 |

## 3. 모듈과 폴더

| 모듈 | 하는 일 | 하지 않는 일 |
|---|---|---|
| `web/` | 입력 폼, URL 쿼리 저장·복원, API 호출, 카드·표·그래프, CSV 만들기 | 계산, Yahoo 호출 |
| `src/main.py` | 라우트, 입력 검사, 종목마다 market → engine 순서로 이어 붙이기, 실패한 종목 모으기, `web/` 정적 파일 제공 | 계산 공식, Yahoo 응답 해석 |
| `src/schemas.py` | 요청·응답 모델 (pydantic) | |
| `src/market.py` | Yahoo 받기, 날짜 보정, 캐시 파일 읽기·쓰기, 종목 검색 | 계산 |
| `src/engine.py` | 매수일, 시뮬레이션, 날마다 평가, XIRR, 그래프용 줄이기 | 네트워크, 파일, "오늘 날짜" 읽기 |

지키는 것 세 가지:

- `engine.py`는 표준 라이브러리만 쓰고 입출력이 없다. 그래서 저장해 둔 fixture만으로 테스트한다.
- 바깥 데이터 출처는 `market.py`만 안다. 바깥에 보이는 함수는 `get_series(symbol)`와 `search(q)` 둘뿐이라, 출처를 바꿔도 엔진과 화면은 그대로다.
- 종목 하나가 실패해도 서버는 죽지 않는다. 실패는 그 종목의 오류로 응답에 담는다.

## 4. 데이터 저장과 갱신

받은 주가는 `data/prices/{종목코드}.json`에 종목마다 파일 하나로 둔다. 캐시일 뿐이라 `data/`를 지워도 다음 요청 때 다시 받는다. 파일 형식은 [상세 설계](4_상세설계.md) 2절.

### DB가 아니라 파일인 이유

- 이 앱은 종목 하나의 전체 기간을 통째로 읽고, 다시 받으면 통째로 바꾼다. DB가 잘하는 일부 조회, 일부 수정, 여러 표 엮기를 쓸 데가 없다.
- 작다. QQQ 상장 이후 전체(약 7,000일)도 수백 KB다.
- 텍스트라 에디터로 열어 바로 확인할 수 있다.
- DB가 필요해지는 때: 사용자가 조건을 저장할 때(v2), 로그인을 붙일 때, 배포 뒤 서버 여러 대가 데이터를 같이 써야 할 때. 그때는 SQLite를 건너뛰고 Postgres 같은 서버형 DB로 간다.

### 언제, 얼마나 받나

- 따로 도는 업데이트 작업은 없다. 계산 요청이 들어왔을 때 저장본이 6시간보다 오래됐으면 그때 받는다. 아무도 안 보는 종목은 받지 않는다.
- 받을 때는 상장 이후 전체를 다시 받는다. 새 날짜만 덧붙이지 않는다.
  - 분할이 생기면 Yahoo가 과거 종가를 전부 다시 계산한다. QLD는 2025-11-20 2:1 분할 뒤 2021-12 종가가 $84.64에서 $42.32로 바뀌었다. 덧붙이기만 하면 분할 전후 값이 섞여 평단가가 조용히 틀린다.
  - Yahoo가 막는 기준은 요청 수인데, 어느 쪽이든 종목당 한 번이다. QQQ 전체는 743KB(gzip 187KB), 0.56초였다. 최근 7일만 받으면 1.7KB, 0.24초다 (2026-11-24 측정).
  - 새 부분만 받기는 요청 한 번에 주는 날짜 수가 제한된 출처로 바꿀 때 다시 본다. 그때는 겹치는 날의 종가를 저장본과 비교해서, 다르면 전체를 다시 받는다.
- Yahoo가 실패하면 저장본으로 계산하고 몇 월 며칠 기준인지 알린다. 저장본도 없으면 그 종목만 오류다.
- 종목 검색 결과는 메모리에 하루 둔다.

## 5. 실행 환경

| | 로컬 (지금) | 배포 ([개발 계획](5_개발계획.md) 8단계) |
|---|---|---|
| 켜는 법 | `실행.bat` 더블클릭 → uvicorn을 켜고 브라우저를 연다 | Docker 이미지. push하면 Render가 배포 |
| 주소 | `127.0.0.1:8010` | `0.0.0.0:$PORT` (HTTPS는 호스팅이 붙여 줌) |
| 캐시 | `data/prices/`가 계속 남는다 | 재시작하면 비워진다. 다시 받으면 된다 |
| 요청 제한 | 없음 | IP당 계산 분당 10회, 검색 30회 |

설정은 환경변수로 받고, 기본값은 로컬 기준이다: `HOST`(127.0.0.1), `PORT`(8010), `DATA_DIR`(data).
