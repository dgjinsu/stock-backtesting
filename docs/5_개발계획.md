## 나중에 배포할 때 막히지 않게

로컬용으로 만들되 아래만 지켜 둔다. 지금 하면 몇 줄이고, 나중에 하면 고칠 곳이 퍼진다.

- 서버 주소·포트는 환경변수로 받는다. 기본은 `127.0.0.1:8010`, 배포 때는 `0.0.0.0:$PORT`.
- `data/prices/`는 지워져도 되는 캐시로만 쓴다. 무료 서버는 재시작하면 디스크가 비워진다.
- XIRR은 뉴턴법으로 풀고, 안 되면 이분법으로 넘어간다. 참고 스크립트(이분법 200회)로 재 보니 4종목 5년 매일이 내 PC에서 0.26초였고 대부분이 XIRR이었다. 뉴턴법으로 바꾸면 0.01초다. 무료 서버 CPU는 내 PC보다 훨씬 약하다.
- Yahoo 호출은 `market.py` 한 곳에서만 하고, 동시에 2개까지만.
- `requirements.txt`는 버전을 고정한다.

## 단계

각 단계는 끝나면 그 자체로 돌아가는 상태가 되게 나눴다. 순서대로 한다.
단계마다 이슈를 하나 이상 만들고 PR로 닫는다 ([개발 워크플로우](7_개발워크플로우.md)). 진행 상황은 [개발 현황판](https://claude.ai/artifact/4qzSDxqhz7o8zoeF2CvucF)에 남긴다.

| 단계 | 할 일 | 끝났다고 보는 기준 |
|---|---|---|
| 0. 개발 준비 | 개발 워크플로우(이슈·PR·자동 리뷰), 에이전트와 슬래시 명령, CI, 코드 컨벤션, 기준값 테스트, 현황판 | CI가 초록. PR을 열면 Claude 리뷰 댓글이 달리고 현황판에 이어져 보임 |
| 1. 뼈대 | `requirements.txt`, `실행.bat`, FastAPI가 `web/index.html`을 띄움, 첫 API 테스트 | `실행.bat` 더블클릭 → 브라우저에 빈 화면 |
| 2. 데이터 | `market.py`: Yahoo 일봉 받기, 날짜 변환, JSON 파일 저장·6시간 재사용, 실패 시 저장값, 검색 | `test_market.py` 통과. QLD를 두 번 부르면 두 번째는 네트워크 안 씀 |
| 3. 계산 엔진 | `engine.py`: 매수일, 시뮬레이션(소수점·정수 주·수수료), 날마다 평가, XIRR, 그래프용 줄이기 | `test_engine.py`가 `expected.json` 모든 사례 통과 |
| 4. API | `/api/backtest`, `/api/search`, 입력 검사, 일부 종목 실패 처리 | `test_api.py` 통과. `/docs`에서 직접 불러 봄 |
| 5. 화면: 입력·요약 | 폼(종목 칩·검색, 기간 버튼, 주기, 금액, 고급), URL 쿼리 저장·복원, 결과 카드와 비교 표 | 예시 조건으로 QLD 평단가 $37.97이 보임. 주소를 새 탭에 열어도 같은 결과 |
| 6. 화면: 그래프·내역 | 그래프 3개(평가금·수익률·주가와 평단가), 로그 축, 매수 내역 표, CSV | 4종목 5년 매일 매수에서 그래프가 부드럽게 움직임. CSV가 엑셀에서 한글 안 깨짐 |
| 7. 마무리 | 오류 문구, 안내 문구, 1024px 폭·다크 모드 확인, README 사용법 | 기능 명세 F-01~F-10을 하나씩 눌러 보고 확인. 시안 "v1" 페이지와 비교 |
| 8. 배포 | 아래 "배포 단계" | 다른 PC 브라우저로 배포 주소를 열어 F-01~F-10 확인 |

3단계를 가장 먼저 해도 된다. 엔진은 fixture만 있으면 네트워크 없이 만들 수 있다.

6단계를 시작하기 전에 그래프 라이브러리를 다시 본다. v2에서 이평선과 낙폭 그래프를 넣으니 Lightweight Charts가 나을 수 있다 ([확장 아이디어](6_확장아이디어.md) 3절).

  - 다시 본 결과 (2026-11-25): v1은 Chart.js 4로 했다. 그래프 3개가 모두 선·계단선이고 툴팁·로그 축·채우기가 기본으로 있으며, 범례와 툴팁 문구를 한국어로 직접 만들기 쉽다. 최대 1,000점이라 성능 차이도 없다. v2에서 이평선·낙폭을 넣을 때 점이 많아지면 그때 Lightweight Charts를 다시 본다.

v1을 끝낸 다음에는 아래 "v2 단계"대로 한다.

## 배포 단계 (8단계)

로컬 버전이 다 된 뒤에 한다. 순서대로.

1. **Yahoo 확인**: Yahoo에서 QLD 종가 하나만 받아 보여 주는 임시 앱을 배포 후보에 올리고 10번 연달아 불러 본다. 클라우드 서버 IP는 집 PC보다 쉽게 막힌다. 막히면 호스팅을 바꾸거나 [상세 설계](4_상세설계.md) 1절의 다른 출처로 `market.py`만 바꾼다.
2. **올리기**: Dockerfile, 호스팅에 GitHub 연결, GitHub Actions CI(0단계에서 만듦)가 통과해야 배포.
3. **공개 방어**: Yahoo 429를 받으면 10분간 캐시로만 응답, 검색 결과 하루 저장, 검색창은 입력이 0.3초 멈춘 뒤 검색, IP당 계산 분당 10회·검색 30회, gzip 압축, `/healthz`, 요청 로그(종목·걸린 시간·Yahoo 결과).
4. **안내**: "개인 프로젝트, Yahoo 비공식 데이터" 표기, 검색엔진 noindex(링크 아는 사람만), "서버 깨우는 중" 표시, 카톡 공유 미리보기(OG 태그).

| 호스팅 | 특징 |
|---|---|
| Render 무료 (추천) | 카드 없음, push하면 배포. 15분 쉬면 잠들어 첫 접속이 1분쯤, CPU 0.1개 (2026년 중반 기준, 가입 때 확인) |
| Cloud Run | 카드 등록, 이 규모면 사실상 무료, 깨는 데 몇 초. 최대 인스턴스 1개와 예산 알림을 걸어 둔다 |
| Fly.io | 월 몇천 원, 항상 켜짐, 저장 파일이 남는다 |

Yahoo 약관은 개인 용도라 공개 서비스는 회색지대다. 링크 아는 사람끼리 쓰는 정도로 두고, 사람이 늘면 데이터 출처를 바꾼다.

## 위험과 대응

| 위험 | 대응 |
|---|---|
| Yahoo가 막거나 응답 형식을 바꿈 | 저장된 데이터로 계속 계산하고 기준일을 표시. `market.py` 한 곳만 고치면 되게 둔다 |
| 클라우드 서버에서 Yahoo가 막힘 | 배포 단계 1에서 코드 올리기 전에 확인한다. 막혀도 로컬 버전은 그대로 쓴다 |
| 분할 직후 저장값과 새 값이 섞임 | 받을 때마다 종목 전체를 통째로 바꾼다 ([아키텍처](3_아키텍처.md) 4절) |
| 원화 평단가 정의 헷갈림 | 화면에 "매수 때 환율로 계산한 평단가"라고 적고, 달러 평단가 × 지금 환율과 다르다는 걸 툴팁으로 |
| 매일 매수 + 긴 기간에서 응답이 큼 | 그래프는 서버에서 1,000점으로 줄이고, 매수 내역만 전체를 보냄 |
| 레버리지 ETF 데이터가 이상해 보임 | [계산 규칙](2_계산규칙.md) 8절처럼 기초 지수 ETF와 비교해 본다. v2에서는 자동으로 찾아 알린다 (F-22) |
| 시안에 기능이 많아 v1이 늘어짐 | v1은 F-01 ~ F-10만 만든다. 시안 "v1" 페이지에 없는 건 v2로 미룬다 |

## 설계 때 확인해 둔 것 (2026-11-24)

- Yahoo `period1=0` 요청이 상장 이후 전체를 일봉으로 준다. `005930.KS`(KRW, Asia/Seoul), `USDKRW=X`(KRW, Europe/London)도 같은 주소로 된다.
- 여름철 `USDKRW=X` 일봉은 23:00 UTC로 찍힌다. 날짜 보정이 필요하다.
- Yahoo 검색은 코드·영문 이름만 찾는다. 한글 이름은 결과가 없다.
- 저장한 fixture: QQQ, QLD, TQQQ, SOXL, USDKRW=X, 005930.KS (2021-01-01 ~ 2026-11-24).
