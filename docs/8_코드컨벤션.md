# 코드 컨벤션

도구가 잡을 수 있는 것은 도구에 맡긴다 (ruff, mypy, pytest). 여기에는 도구가 못 잡는 약속을 적는다.
구조를 이렇게 나눈 이유는 [아키텍처](3_아키텍처.md) 3절에 있다.

## 1. 공통

- 파일은 UTF-8, 줄 끝은 LF다 (`.editorconfig`, `.gitattributes`). `실행.bat`만 CRLF.
- 이름(변수·함수·파일·API 필드)은 영어, 주석·docstring·문서·화면 문구는 한국어로 쓴다.
- 한 줄은 100자 안쪽. 들여쓰기는 Python 4칸, HTML·CSS·JS·JSON·YAML 2칸.
- 날짜는 `YYYY-MM-DD` 문자열이나 `datetime.date`로 주고받는다. 시각이 필요하면 시간대를 붙여 다룬다.
- 금액·비율의 반올림은 계산 규칙이 정한 자리에서 응답을 만들 때 한 번만 한다. 계산 중간에는 반올림하지 않는다.

## 2. Python

### 모듈 경계

| 모듈 | import해도 되는 것 | 안 되는 것 |
|---|---|---|
| `src/engine.py` | 표준 라이브러리 | `httpx`, `fastapi`, `pydantic`, 다른 `src` 모듈, 파일·네트워크, `date.today()` |
| `src/market.py` | 표준 라이브러리, `httpx` | `src.engine`, `src.main`, `fastapi`, `pydantic` |
| `src/schemas.py` | `pydantic` | `src.engine`, `src.market` |
| `src/main.py` | 위 모두, `fastapi` | |

- engine의 입력과 출력은 `@dataclass(frozen=True, slots=True)`로 정의한다. API 모양(pydantic)과 계산 모양(dataclass)을 섞지 않고, 둘 사이 변환은 main이 한다.
- 오늘 날짜, 환경변수, 설정은 main에서 읽어 인자로 넘긴다.
- 모듈 바깥에 보이는 함수는 적게 둔다 (market은 `get_series`, `search`). 나머지 이름은 `_`로 시작한다.

### 스타일

- 함수·메서드에는 타입 힌트를 모두 단다. `mypy --strict`가 `src/`와 `scripts/`를 본다. `Any`는 Yahoo 응답처럼 바깥에서 들어온 JSON을 처음 받는 곳에만 쓴다.
- 이름: 함수·변수 `snake_case`, 클래스 `PascalCase`, 상수 `UPPER_SNAKE`. 단위가 헷갈리는 값은 이름에 단위를 붙인다: `amount_krw`, `fee_pct`, `fx_rate`, `return_pct`.
- 공개 함수에는 docstring을 단다. 계산 공식이면 계산 규칙 몇 절인지 적는다: `"""평단가. 계산 규칙 4절."""`
- `print` 대신 `logging`을 쓴다. 로그에는 종목, 걸린 시간, 결과를 남긴다.
- 예외: market은 `MarketError` 하나를 바깥에 던지고, 메시지는 사용자에게 보여 줄 한국어로 쓴다. main은 종목 하나의 실패를 응답의 `errors`에 담고 서버는 계속 돈다. 맨 `except:`와 `except Exception: pass`는 쓰지 않는다.
- 비동기: 바깥 호출은 `httpx.AsyncClient`로, 동시에 2개까지(`asyncio.Semaphore(2)`), 타임아웃을 꼭 준다.
- 경로는 `pathlib.Path`. 종목 코드로 파일 이름을 만들 때는 허용 문자(`A-Z a-z 0-9 . - = ^`)만 남겨 경로 조작을 막는다.

### 테스트

- 파일은 `tests/test_<모듈>.py`, 이름은 `test_<대상>_<조건>_<기대>` (예: `test_buy_days_monthly_anchor_on_holiday_picks_next_trading_day`).
- 네트워크를 쓰지 않는다. Yahoo 응답은 `tests/fixtures/yahoo/`, HTTP는 `httpx.MockTransport`로 흉내 낸다. 실제 Yahoo를 불러 보는 확인은 `@pytest.mark.live`를 붙이고, 기본 실행과 CI에서 빠지며 `pytest -m live`로만 돈다.
- 기준값은 `expected.json`이나 문서의 표에서 읽는다. 테스트 안에서 기준 공식을 다시 구현해 기댓값을 만들지 않는다.
- 허용 오차는 계산 규칙 7절을 따른다: 평단가 ±0.01, 수량 ±0.0001, 금액 ±1원, 수익률 ±0.01%p. `pytest.approx(abs=...)`로 쓴다.
- 여러 사례는 `@pytest.mark.parametrize`에 `ids`를 붙여 나눈다. 공통 준비는 `tests/conftest.py`의 fixture로 둔다. 다만 parametrize가 수집 단계에서 읽어야 하는 데이터(기준값, fixture 파서, 가짜 Yahoo)는 fixture로 넘길 수 없어서 `tests/helpers.py` 모듈에 두고 import한다 (`tests`는 패키지).
- 실패 경로도 테스트한다: 없는 종목, 기간 안에 매수일 없음, 저장본만 있을 때, 환율 없는 날.
- `tests/reference_calc.py`는 기준을 만든 스크립트라 린트·포맷에서 뺀다. 고치면 `tests/test_reference_calc.py`가 expected.json과 같은지 확인한다.

## 3. API

- 경로는 `/api/...`, 필드는 `snake_case`다. 모양은 [상세 설계](4_상세설계.md) 4절을 그대로 따른다.
- 입력 오류는 422와 항목별 한국어 메시지로 돌려준다. 종목 하나의 실패는 200 응답의 `errors`에 담는다.
- 응답 숫자는 계산 규칙의 자리수로 반올림해서 보낸다. 화면은 받은 값을 그대로 보여 준다.

## 4. 웹 (HTML·CSS·JS)

- 빌드 도구 없이 ES 모듈(`<script type="module">`)로 쓴다. 전역 변수를 만들지 않는다.
- JS 스타일은 Prettier 기본값(2칸, 큰따옴표, 세미콜론)을 따른다. v1은 npm 의존성을 두지 않으려고 JS 린터를 쓰지 않고, `scripts/check.py`가 `node --check`(문법)와 `node --test`(테스트)만 돌린다 (2026-11-24 결정). Node.js 22.7 이상(package.json 없이 ES 모듈을 알아보는 버전)이 필요하고, 없으면 로컬에서는 건너뛴다.
- DOM을 쓰지 않는 로직(조건, 표시 형식, 그래프 데이터 만들기)은 따로 모듈로 떼어 `tests/web/*.test.mjs`에서 시험한다. 화면 모듈(`app.js`, `charts.js`)은 브라우저에서 확인한다.
- 데이터는 `textContent`로 넣는다. 서버나 URL에서 온 값을 `innerHTML`에 넣지 않는다.
- 숫자는 `Intl.NumberFormat('ko-KR')`로 표시한다. 손익 색은 미국식(이익 초록, 손실 빨강)이고 부호(+/−)를 같이 쓴다. 색만으로 뜻을 전하지 않는다.
- 색·글꼴·간격은 `style.css`의 CSS 변수(시안의 토큰)로만 쓴다. 라이트와 다크를 둘 다 확인한다.
- 폼 컨트롤마다 `<label>`을 단다. 키보드만으로 모든 기능을 쓸 수 있고 포커스가 보여야 한다.
- 조건은 URL 쿼리에 담는다 (F-09). `localStorage`에는 화면 편의(접힘 상태 등)만 둔다.

## 5. 의존성

- 실행에 쓰는 라이브러리는 `requirements.txt`, 개발 도구는 `requirements-dev.txt`에 버전을 고정한다 (`==`).
- 새 라이브러리를 더하려면 PR 본문에 이유와 대안을 적는다. [아키텍처](3_아키텍처.md)의 "고르지 않은 것"과 부딪히면 문서부터 고친다.
- 브라우저 라이브러리(Chart.js 등)는 버전을 고정한 주소로 불러오거나 `web/vendor/`에 둔다.

## 6. 문서

- 동작·API·계산이 바뀌면 같은 PR에서 docs/를 고친다.
- 결정을 바꾸면 [개발 계획](5_개발계획.md) "시작 전에 정할 것" 표나 해당 문서에 날짜와 이유를 적는다.
