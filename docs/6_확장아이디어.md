## 1. 이평선 조건 적립

### 전략 예

| 전략 | 규칙 |
|---|---|
| 떨어질 때 더 사기 | 매수일 종가가 200일선 아래면 2배, **위면 절반** |
| 과열 때 덜 사기 | 이평선보다 20% 넘게 위면 절반만 |
| 레버리지 전환 | 기준 종목(QQQ)이 200일선 위일 때만 QLD를 산다. 아래면 사지 않고 현금으로 쌓았다가, 위로 올라오면 쌓인 현금까지 산다 |

- 처음에는 "떨어질 때 더 사기"를 "아래면 2배, 위면 1배"로 적었다. 그런데 아래 "같은 예산" 방식으로 계산하면 현금이 쌓일 틈이 없어서 2배로 살 돈이 없고, 결과가 기본 적립과 똑같았다 (2026-11-24 확인). 그래서 위일 때 절반으로 바꿨다.
- 2026-11-24 계산 결과(QLD, 5년, 매월 200만원)는 [계산 규칙](2_계산규칙.md) 9-8절에 있다. 레버리지 전환이 수익률 +92.83%, XIRR 26.78%, 최저 수익률 −24.8%로 기본 적립(+88.19%, 25.75%, −39.4%)보다 나았다.

- 그래프: 주가 그래프에 20·60·120·200일선을 겹쳐 그린다.
- 이평선 기간과 배수는 화면에서 고른다.
- 지금은 사기만 한다. 이평선 아래로 내려가면 보유분을 파는 전략은 매매 엔진이 되는 일이라 따로 판단한다.

### 공정하게 비교하기

더 사는 전략은 넣은 돈이 달라진다. 평가금으로 비교하면 많이 넣은 쪽이 당연히 커 보인다. 그래서 **같은 예산** 방식을 기본으로 한다.

- 매번 A를 현금에 넣는다. 투자금은 기본 적립식과 똑같이 매번 A씩 늘어난다.
- 규칙이 정한 만큼(A × 배수) 현금에서 꺼내 산다. 현금이 모자라면 있는 만큼만 산다.
- 안 쓴 현금은 평가금에 넣는다. [계산 규칙](2_계산규칙.md) 4절의 정수 주 모드에서 남은 돈을 다루는 방식과 같다.
- 결과는 기본 적립식과 나란히 놓고 평단가, 수익률, XIRR, 최저 수익률로 비교한다.

### 미래 데이터 금지

- 매수일의 이평선은 그날 종가까지로만 계산한다. 종가에 사니까 그날 종가는 넣어도 되지만, 다음 날 데이터는 절대 안 된다.
- 200일선은 상장 후 200거래일이 지나야 생긴다. 그 전에는 배수 1로 산다.

### 엔진에 붙이는 법

- `Params`에 규칙(없음 / 떨어질 때 더 / 과열 때 덜 / 레버리지 전환)과 이평선 기간, 배수를 추가한다.
- 매수 금액을 정하는 곳에 배수만 곱한다. 이평선 계산은 엔진 안에서 몇 줄이라 라이브러리가 필요 없다.
- 규칙이 "없음"이면 지금 계산과 똑같다. 그래서 `expected.json` 기준값이 그대로 회귀 테스트가 된다.

## 2. AI

### 2-1. MCP 서버로 엔진 열기 (추천)

Claude 데스크톱이나 Claude Code에서 "QLD랑 TQQQ 5년 매달 200만원 비교해 줘"라고 하면, Claude가 이 엔진을 도구로 불러 계산하고 대화로 답한다.

- `src/mcp_server.py` 하나를 추가한다. 공식 MCP 파이썬 SDK(`mcp` 패키지)로 `market`과 `engine`을 감싼다. `main.py`가 하는 일과 같고 입구만 다르다.
- 도구는 두 개: `backtest`(종목, 기간, 주기, 금액, 통화)와 `search`(검색어).
- 돌려주는 것은 요약 지표만이다. 매수 내역 전체는 대화를 금방 채우니 넣지 않는다.
- 비용이 없다. LLM은 쓰는 사람의 Claude다.
- 이력서에 "AI 에이전트 도구 연동"으로 쓸 수 있다.

### 2-2. AI 결과 해설

결과 아래에 "AI 해설" 버튼을 두고, 누르면 3~5문장으로 결과를 풀어 준다. 예: "평단가는 $37.97이고 지금 가격은 그 1.9배다. 다만 2022년 6월에는 −39%까지 빠졌던 구간을 버텨야 했다."

- 넘기는 것은 엔진이 계산한 요약 지표(JSON)뿐이다. 주가 원본은 넘기지 않는다.
- 지킬 것: 숫자는 입력에 있는 것만 쓴다. 종목 추천과 전망은 하지 않는다 ([기능 명세서](1_기능명세서.md)의 "안 한다"). 화면에 "AI가 쓴 해설"이라고 표시한다.
- API 키는 환경변수로 받고 git에 넣지 않는다.

| 모델 | 가격 (100만 토큰당, 입력/출력) | 한 번에 (입력 2천·출력 1천 토큰 가정) |
|---|---|---|
| Claude Opus 5.5 (기본) | $4 / $20 | 약 $0.03 (40원). 생각 토큰은 출력으로 따로 붙는다 |
| Claude Haiku 5.5 | $0.10 / $0.50 | 약 $0.0007 (1원) |

가격은 2026-11 기준이다. 쓰기 전에 다시 확인한다.

배포하면 남이 누를 때마다 내 돈이 나간다. 그래서:
- 버튼을 눌러야 만든다 (결과가 나올 때마다 자동으로 만들지 않는다).
- 하루 한도를 둔다.
- 같은 조건(URL)의 해설은 저장해 두고 다시 쓴다.

### 2-3. 자연어 조건 입력 (보류)

"매주 월요일 50만원씩 QLD 5년" → 입력 폼을 자동으로 채운다. 구조화 출력으로 쉽게 되지만, 폼이 이미 간단해서 얻는 게 적다. MCP 서버를 만들면 사실상 같은 경험이 된다.

### 2-4. 주가 예측 (안 함)

- 과거 데이터에 맞춘 모델은 백테스트에서만 좋아 보이기 쉽다 (과적합).
- 예측을 보여 주는 순간 "종목 추천 안 함"과 부딪힌다.
- 이 앱의 가치는 "과거에 이렇게 했다면"을 정확히 보여 주는 데 있다.
